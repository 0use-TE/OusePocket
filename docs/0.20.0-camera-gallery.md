## 资源管理

摄像头不是应用私有驱动。系统 `ouse_camera` 服务拥有硬件、采集、JPEG 编解码和照片 I/O；应用只能提交有界任务，不能取得 DMA 指针、文件句柄或操作任意路径。一个应用实例可独占摄像头，其他实例请求失败并可通过 `inUse` 判断占用。预览本身登记为可取消、关闭即停止的原生 `camera/preview` 任务。

应用进入后台会停止预览；关闭、故障和卸载通过实例所有者回收。熄屏、系统静默退出及取消预览任务也释放硬件。重新进入相机时启动，熄屏后留在相机页面可点击重试。原生工作完成后才释放对应缓冲，系统重启排空流程等待相机服务空闲。线程栈、传感器帧、预览、缩略图及 UI 图像副本使用 PSRAM；不把大图传入 QuickJS 堆。框架统计包含实例自己的原生图像副本，不冒充全局摄像头 DMA 的精确内存归属。

上电不会打开摄像头。只有获授权的前台应用显式调用 `start()` 才启动硬件。相册不启动摄像头。

停止流、关闭设备或反初始化未确认成功时，不释放 DMA 缓冲或把硬件转交其他应用；系统保留占用并低频重试，通过 `recoveryPending` 报告恢复状态。持续失败需要按硬件复位键重启，不冒险释放仍可能被 DMA 使用的内存。不建议带电插拔摄像头排线。

## JavaScript API

Manifest `capabilities.camera=true` 允许取景；拍照另外需要 `files=true`。`photos=true` 单独允许读取 SD 卡 `Ouse/Pictures/` 的 JPEG 文件与缩略图。缺少权限不能引用对应的原生图片 ID，也不能通过这些接口访问别的应用预览。

```js
const state = Ouse.camera.get();
const taskId = Ouse.camera.start();
Ouse.camera.stop();
const captureId = Ouse.camera.capture();

const listId = Ouse.photos.list(0);
const photos = Ouse.photos.get();
const openId = Ouse.photos.open(photos.entries[0].path);
```

请求返回任务 ID，拒绝返回 `false`；未获对应权限的 `get()` 返回 `null`。`get()` 只读取缓存，包含 `running/busy/inUse/recoveryPending/error/taskId/revision/path`；相册还包含 `offset/more/entries`。每个应用实例仅允许一个待处理请求，服务队列容量 8；任务结果由 `Ouse.tasks.onComplete` 交付，不在 UI 或 JS 回调内执行摄像头和 SD I/O。

JSON 图片控件可使用 `src:"@camera"`、`src:"@photo"` 和 `src:"@thumb0"` 至 `"@thumb5"`。它们不是 BPK 资源，也不会进入资产列表；由框架在 UI 线程复制最新像素并使缓存失效。大图/预览为 320×240 显示副本，缩略图 128×96，按比例显示而不拉伸。JPEG 原图仍保存为 1280×960，不等于取景控件大小，也不宣称交付 5 MP 全分辨率拍摄。

## SD 卡与应用

- 相机 `user.camera`：实时取景、重试、拍照。按下拍照时检查 SD 卡，底层还会再次验证。没有卡、不可读、空间不足或被拔出时提示失败，不回退内部 Flash。
- 相册 `user.gallery`：必须有可用 SD 卡，否则弹出提示。两列缩略图，可上下滚动，每组最多 6 张；上一组/下一组有界浏览，点击查看大图，再返回相册。不提供照片删除、录制视频、变焦或扫码。
- 文件路径固定在 `Ouse/Pictures/`。照片名包含时间、启动随机数和递增编号，临时文件以排他方式创建，写完并同步后才发布为 `.jpg`；取消和失败清理本次临时文件，不自动格式化 SD 卡。
- 相册支持 `.jpg`/`.jpeg`；单文件上限 4 MiB、解码尺寸最高 2560×1920。损坏或不支持的照片不能解码时不影响整个系统，查看时提示失败。不会自动导入或删除卡中原有照片。

原生 C 接口见 `components/ouse_camera/include/ouse_camera.h`；板级硬件适配位于 `boards/waveshare_lcd35/board_camera.c`。当前只适配此板的 OV5647，不宣称支持任意 CSI 摄像头。
