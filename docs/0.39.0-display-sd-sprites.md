# Core 0.39.0 / Native API 41

本版提供可选的手动横竖屏、按应用隔离的 SD 文件服务、精灵图集与批量布局接口。应用可以完全不调用这些新接口。屏幕仍受 SPI 带宽和无 TE 同步信号限制，旋转与动画不等于消除硬件撕裂。

## 屏幕与布局

下拉面板以“屏幕方向”替换原电池操作按钮，电量仍显示在状态栏。方向只在当前运行会话保留，重启回到竖屏。状态栏、桌面、应用容器、三键导航、返回手势、输入法、系统弹窗及最近任务随逻辑尺寸调整。锁屏与首次设置期间不接受旋转。

下拉面板保留音量、亮度等全部控制，内容超出屏幕时纵向滚动，并显示自动滚动条。横向滑动仍用于面板切换。

```js
Ouse.display.setOrientation('landscape'); // 或 portrait；返回是否接收请求
Ouse.display.onChange(function () { /* 按 get() 中实际视口尺寸重新布局 */ });
Ouse.ui.layout([{id: 'field', x: 8, y: 52, width: 464, height: 132}]);
```

旋转仅允许正常运行的前台应用请求，由 UI 线程异步执行。layout 使用页面逻辑单位，每批最多 64 项；全部节点及数值验证通过后才提交。需要响应横竖屏的应用应监听显示变化，使用实际应用视口，避免把屏幕尺寸当成可用内容尺寸。

## 专属 SD 文件

清单声明 `sdcard: true` 后使用 `Ouse.sd`，路径根目录固定为 `/sdcard/Ouse/Apps/<应用 ID>/`，调用者只能传相对路径。绝对路径、上级目录、隐藏组件和内部临时文件名被拒绝。未插卡时操作拒绝，不会格式化存储卡。

- `get()`：缓存的存储卡状态。
- `list(path, offset=0)`：每页最多 16 项，返回 entries、more、nextOffset。
- `stat(path)`、`mkdir(path)`、`remove(path)`、`rename(from,to)`。
- `read(path,offset,length)`：每次最多 4096 字节，返回 ArrayBuffer。
- `write(path,buffer)`：最多 4096 字节，临时文件加备份替换；覆盖失败尽量恢复原文件。
- `writeChunk(path,buffer,offset)`：每次最多 4096 字节，原位分段写；文件与偏移上限 128 MiB。
- `download(path,url)`：还需 network 能力，原生流式下载，最多 128 MiB、总期限 30 秒。

上述异步操作返回带 taskId 的 Promise，沿用系统任务取消接口，关闭应用取消所属任务。rename 不覆盖现有目标，remove 只移除文件或空目录。分段写不提供整文件事务。卸载/清除内部数据仍保留 SD 文件，当前没有自动递归清理应用文件夹。

录音机 1.1.0 将录音保存到自己的 `Recordings/` 目录，播放、命名、删除绑定所属应用，不再依赖公共录音目录。

## 精灵与可选游戏循环

页面节点 `type: 'sprite'` 从包内透明 ARGB 图集中按网格裁剪帧；属性包括 src、frameWidth、frameHeight、firstFrame、frameCount、frame、fps、playing、loop。帧率为 1～30，原生 UI 推进帧动画；暂停应用时冻结。图集沿用包内图片大小、数量和总内存上限。

```js
Ouse.sprites.update([{id:'hero', x:40, y:60, playing:true, fps:8}]);
```

每批最多 32 个精灵，先校验再整体提交。显式设置帧或帧区间重新开始；停止播放保留当前帧。脚本定时器最短 33 ms，示例采用 50 ms 游戏循环，暂停和关闭时停止。接口不暴露 LVGL 指针；这是一组有界的图形和调度能力，不是完整游戏引擎。

## 旧应用适配补充

系统旋转不会自动重排所有旧应用。2048 的原上下布局在横屏时将棋盘压扁；1.1.0 改为竖屏上下排列、横屏左侧方形棋盘及右侧分数/新局，监听实际视口变化，不重置局面。计算器 1.1.0 横屏将数字键盘独立放在右侧，左侧扩展功能纵向滚动；竖屏空间不足时整页可滚动，不再将五排数字键压缩到不可读高度。两包要求 API 41，固件无需重烧。

本地应用脚本验证覆盖 320×416、320×400、480×256、480×240 四种视口、2048 合并得分/旋转保持进度，以及计算器三种模式/基本计算。不能据此宣称所有商店应用已完成横屏适配。

两包已安装到真机并发布商店。真机四次方向切换验证 16 个格子正方形且全部可见、实际滑动派发，计算器实际点击 2+3=5 并检查科学模式；最终 heap ok、errors=0、live=0，恢复竖屏桌面。结果 `.tools/diagnostics/g2048-result.json`，界面截图 `g2048-after-landscape.jpg`、`calculator-after-landscape.jpg`、`calculator-after-science-landscape.jpg`。商店、文件管理横屏首页亦查看正常；空相册截图不能代替有内容时的完整适配验证。一次测试重启遇到 C6 SDIO 初始化超时，经 ROM 复位恢复；这是独立的启动稳定性问题，本次未宣称已修复该底层原因。

网易云 1.0.1 在横屏冷启动时，旧固定坐标 transport.y=276、volume.y=344 超过 256dp 内容高度，原生页面加载到第 5 个节点时拒绝，错误为 Invalid page.json or app.js。1.1.0 将初始模型改为两种方向均可校验的范围，再按实际视口布局；横屏唱片在左、操作在右，竖屏上下排列。已通过本地 COM10 验证横竖屏加载、六个媒体按钮可见、无新增脚本错误及 heap ok；保留用户原有权限拒绝状态，未验证配对后的媒体控制。包已发布商店。证据 `.tools/diagnostics/netease-fixed-20261020-083803/`。
