# 0.19.0 原生应用管理

入口：设置 → 应用管理。应用列表使用真实应用图标，详情提供应用 ID、应用包大小、本地数据大小、合计，以及打开应用、清除数据和卸载。设置本身标记为包含在系统固件中，不允许清除或卸载。这里不展示运行时 RAM，也不伪造单独的缓存分类。

大小按实际 BPK 文件和应用私有 JSON 文件的逻辑字节计算，不包含 LittleFS 块开销；原生闹钟独立显示条数，不把共享闹钟数据库整文件重复计入每个应用。应用存储可用空间来自 LittleFS 实际统计。SD 卡文件不计入私有数据。

## 所有权与恢复

原生设置只读取 PSRAM 中的缓存，并向容量为 1 的队列提交请求。安装器任务统一拥有应用包、串口安装和管理操作；私有目录统计与清理由存储任务串行执行。串口上传、系统静默退出和其他管理操作进行时拒绝冲突请求，不在 LVGL 回调中执行文件 I/O。不向普通 BPK 暴露跨应用清理接口。

清除数据需二次确认。先持久化独立的 `reset.pending` CRC 日志，再关闭目标应用并禁止重开，清除该应用的媒体、原生闹钟和私有数据；保留 BPK，完成后解锁。卸载沿用 `remove.pending` 日志，移除应用注册、应用包及其私有数据。两个操作均保留 SD 卡文件，失败保留恢复状态、提供重试，重启后恢复未完成操作。对损坏日志采取保守失败，不自动删除未知对象。

## 验证

- `python tools/test-app-manager.py`：真实管理桥接组件，验证系统应用保护、目标 ID 复制、请求串行化、上传/恢复互斥、完成状态和有界目录缓存。
- `python tools/test-ouse-reliability.py --checks journal`：真实日志及安装器清理函数，验证 CRC、原子提交失败、每个卸载阶段和五个清理阶段失败后重试、清理保留应用包、恢复日志相互隔离。
- `python tools/test-device-app-manager.py --port COM5`：通过真实触摸输入操作原生设置，只安装并清理两个临时 QA 应用；校验大小、清除/卸载的取消及确认、闹钟清理、对照应用隔离、设置保护、SD 文件 CRC、运行时与堆检查，最后恢复原有安装列表。

已在家中电脑的实际 COM5 更新应用区 `0x10000`，未擦除 NVS、LittleFS 或 SD 卡。最终 BIN 5,062,496 字节，8 MiB 应用分区剩约 40%；SHA-256 `2789047a48a9f410104fd919bbf8be09b37947838f24c6b17ea76d1cd53ff3f3`。配对 ELF SHA-256 `222bf722cd9efddfe0226a9c38f4606ff54d508e3449ab09b0dcbe00feb0e0eb`，重启后通过 `DBG_BUILD` 核对一致。

真实触摸验证通过：测试包 1,474 字节、私有数据 34 字节、合计 1.5 KiB；取消清除保留数据，确认清除后数据为 0、闹钟消失、包仍存在且可打开；对照应用的数据和闹钟不变；卸载的取消与确认、设置应用的保护均通过。测试额外中断了一次串口上传并等待 31 秒，确认超时后应用管理恢复可用。修复了只读串口调试被误认为安装忙、上传超时未释放管理忙状态的问题。

两款临时 QA 应用已清理；测试前后以及重启后的 16 个原有应用 ID 完全一致。SD 示例音乐仍为 `480044:abaad727`（字节数:CRC32）。重启后的 JS 上下文、错误、待处理存储请求均为 0，堆检查 `ok=1`；此时内部空闲 63,671 字节，PSRAM 空闲 27,644,524 字节，不是全部应用运行后的峰值。COM5 已释放。
