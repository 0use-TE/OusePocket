# 0.20.1 camera open fix

The physical board detected OV5647 PID 0x5647, but failed while registering
`video0` with the VFS. The default eight VFS registrations were already used by
system services. Set `CONFIG_VFS_MAX_COUNT=20` in both the build configuration
and defaults, matching the esp_video example's documented remedy. This changes
the number of registered filesystems/devices, not SD formatting or file limits.

Remove the camera's status label entirely. Opening failures appear only in a
dismissible dialog; periodic refresh does not add explanatory text or reopen it.
The shutter button alone indicates an active save operation. Retain SD checks.

Board logs identify successful stream initialization and the first valid frame,
so a successful sensor probe cannot be mistaken for working frame capture.

Physical COM5 verification: application firmware flashed with hash verification;
camera BPK replaced successfully; HELLO reports 0.20.1. Opening the camera logs
`Streaming 1280x960 RGB565; buffers in PSRAM` followed by the first valid
2,457,600-byte frame. After 18 seconds the runtime reports zero script errors;
the visible UI tree contains only the title, retry and shutter labels, with no
failure dialog or status text. No photograph was taken and no SD data erased.
