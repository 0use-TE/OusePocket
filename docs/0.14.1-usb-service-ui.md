# 0.14.1 USB 控制与服务面板

设置 → USB OTG 只保留「USB 音频」「USB 网络共享」两行开关，删除状态说明和底部小字。没有完成 USB 枚举、挂起或系统正在收尾时，两行均禁用，事件提交时再次检查条件。网络共享还要求 Wi-Fi 上游可用、网段不冲突；已经开启时允许关闭，避免断网后无法停止共享。

「USB 音频」只控制板级音频请求，不断开 USB 组合设备，电脑仍能检测到连接。关闭后停止音频工作任务，等待实际停止；重新开启时通过会话 generation 触发新任务，即使电脑没有重新选择流也能恢复。开关默认开启、不持久化。原生 `ouse_usb_set_enabled()` 仍用于系统控制；不把整个组合设备断开按钮作为只能连接后操作的开关，否则关闭后将无法从界面恢复。

只读 `Ouse.usb.get()` 新增 `audioEnabled`，与 `audioRunning`、主机 speaker/microphone 请求分别表示功能许可、实际运行和主机选流。C API 14、JS API 1。依赖、分区、字体不变。

后台活动与服务改为概览卡片、按需创建的活动卡片、八项服务的双列图标网格。活动卡片与服务网格仅在该页面可见时创建，离页回收；设置暂停时同步释放，避免继续占用另一应用启动所需的内存。显示应用名称、原生/脚本类型、停止状态；停止按钮禁用时不能重复请求，按下期间冻结身份映射。无活动有空状态；恢复按钮仅在收尾失败时出现。点击概览查询收尾阻塞原因，点击服务查看原始错误、任务数和最早活动时长；主页面不再堆叠这些诊断文字。继续读取原有 2 Hz 有界快照，无 UI 硬件 I/O。

## Windows 使用音频与麦克风

用支持数据的线连接板子的 USB OTG Type-C，保持设备端 USB 音频开启。Windows 11 使用自带 UAC2 驱动，无需安装独立软件。

1. 电脑「设置 → 系统 → 声音 → 输出」选择 **Ouse Pocket USB**，电脑播放声音就送往板子扬声器。
2. 「输入」选择 **Ouse Pocket USB**，Windows 录音机、会议软件即可使用板子麦克风。应用仍需 Windows 麦克风权限。
3. 也可在软件中分别指定输入/输出设备，无需修改电脑所有应用的默认设备。

当前 USB 音频是 16 kHz、16 位单声道，Windows 负责应用格式转换；当前实现适合语音与基础播放，不代表高保真立体声。音频与麦克风不需要开启 USB 网络共享。共享默认关闭；本轮验证保持关闭，避免 Windows 自动切换默认网关。

## 音频缓冲分配修正

本轮实机发现：冷启动后先反复浏览设置，再首次播放音乐时，原先按需建立 I2S 通道的路径可能分配 DMA 缓冲失败。仅释放服务卡片不足以解决该路径。原生音频工作任务现在在启动时准备已有的固定双工 DMA/codec 缓存，通道保持停止、不录音、不播放；其大小、64 帧周期及唯一音频硬件所有者不变。失败仍走正常的重试/错误路径，启动日志记录准备结果及 DMA-capable 空闲字节。缓存继续按既有约定保留复用，操作结束不代表这些缓存已释放。
