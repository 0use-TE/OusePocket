# Core 0.28.0：应用蓝牙与 HID

原生 API 31，JS API 1。`Ouse.bluetooth` 是当前应用实例独占的一条 BLE 连接，模式为 `central` 或 `hid`。系统设置里的开关、搜索、配对和忘记绑定仍由 0.27 的蓝牙页负责。应用不能开关蓝牙、不能删除全局绑定，也不能代替用户确认配对。

## 应用接口

`open` 需要 manifest 的 `bluetooth` 能力和已授予的蓝牙权限。`hid` 还要 `hid` 能力、输入控制权限，并且应用在前台。`close`、暂停、脚本故障、权限撤销和任务取消都会结束这次会话。

同时只有一个连接。地址类型 0 是公有地址，1 是随机地址，2 是公有身份地址，3 是随机身份地址。`connect(address, addressType)` 接受 0 到 3。Windows 把自己的公有 MAC 扫描成类型 2；只允许 0 和 1 时，应用连不上这台电脑。

中央模式可以扫描、连接、发现服务、特征和描述符，以及读、写、订阅。16 位 UUID 文本带 `0x` 前缀，CCCD 是 `0x2902`。128 位 UUID 是小写带连字符的形式。

HID 报告是键盘、Consumer Control 和相对鼠标。键盘用法 104 对应 F13。报告图外观 `0x03C1`，PnP 厂商标识 `0x02E5`，产品标识 `0x0028`。没有主动松开时，两秒后固件把仍按住的报告清掉。这不是经典蓝牙，也不向应用开放自定义 GATT 服务端。

## 验证记录（2026-10-19）

验收固件只刷了 P4 的 `0x10000` 应用分区，没有刷 C6、NVS、LittleFS、SD、bootloader 或分区表。`ouse_core_desktop.bin` 大小 5,567,728 字节，SHA-256 为 `5a8806dcf3bddeb68747baf7421a643dd54d8386d19490c6cc35ffcb3fafe925`。离线 `tools/test-ble-service.py` 覆盖身份地址解析和忘记绑定时的地址类型。

家里的 Windows 电脑先解除配对。板子忘掉 `5C:80:B6:5C:50:0C` 后 `bonds=0`，再广播。两端数字比较码都是 `260287`，板子进入 `encrypted=1,bonded=1`。口袋地址是 `E8:3D:C1:D2:43:0E`。电脑上仍留着旧绑定时，新的配对会被拒绝，不会弹出数字比较。

同一条新配对的 HID 链路上，临时应用把 F13 送到这台电脑。原始输入设备路径包含 `e83dc1d2430e`，VID `0x02E5`，PID `0x0028`。

- 短按后 0.177 秒收到松开。
- 按住不放，2.074 秒收到自动松开。
- 应用调用 `close` 结束会话后，从按下到松开是 0.922 秒，早于两秒保护。这次间隔里包含测试脚本点下「关闭连接」之前约 0.6 秒的界面等待。
- 同一次记录里还有第三次松开，间隔 2.079 秒。那一次用调试命令关闭整个应用，界面拆卸没有赶在两秒保护之前，主机收到的是保护释放。按键仍然松开了。

应用作为中央设备连接这台电脑上的临时 GATT 服务，完成发现、读、写和通知。屏幕结果是 `GATT 通过 79,117,115,101,80,52`，即写入的 `OuseP4`。

验收后卸载 `user.ble.probe`。自检 `ok=1`，运行时实例、上下文、控件和定时器都是 0，`errors=0`。内部空闲 55,915 字节，最大连续块 30,708 字节；这次 HID 会话看到的内部最小剩余是 9,376 字节。PSRAM 空闲 27,275,020 字节。这不是长期运行或其他应用同时工作时的内存余量。Windows 上为这次验收建立的计划任务已删除。绑定仍留在板子和这台电脑上。

范围仍不包括经典蓝牙、蓝牙音频，以及除上述键盘、媒体键和相对鼠标以外的 HID 设备。
