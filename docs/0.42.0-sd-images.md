# Core 0.42.0：启动时加载 SD 高清图像（Native API 44）

修复勇者之路首关背景的缩图放大问题。旧村庄图 192×46 拉伸至 1620×385，旧远景 96×48 拉伸至 930×330，原图细节已经丢失。新版本从原始导出图直接生成 1620×385 村庄和 930×330 远景，渲染时按 1:1 采样，保留透明背景与分层视差。

完整背景共 3,722,400 字节 BGRA 像素，存入 SD 的 `Ouse/Pictures`；应用包仍保留旧小图作为资源缺失时的回退。512 KiB BPK 上限不变。

```javascript
// 须在 app.js 的同步初始化阶段调用，需 capabilities.files。
const loaded=Ouse.assets.loadImage('village-hq','Pictures/brave-road-village-hq-v1.bin');
// 成功后按普通图片资源 ID 使用，Canvas/sprite 不读取 SD 文件。
Ouse.canvas.submit('world', [{op:'drawImage',src:'village-hq',x:-60,y:-144,
    width:1620,height:385,sourceWidth:1620,sourceHeight:385}]);
```

仅允许既有共享文件目录的相对路径，通过现有文件租约打开。图像格式为 OIC1，8 字节头 + 精确长度的 BGRA8888 像素，尺寸每边最多 2048，SD 图像累计最多 4 MiB。与包内资源合计最多 16 项。文件缺失、越界、截断、尾随字节、权限不足、内存不足或重复 ID 均不发布资源；返回 false。错误参数抛 TypeError。

描述符和像素发布后不可替换。该 API 仅同步初始化阶段可用；应用 ready 后返回 false。原子图像数量发布保证 UI 只能看到初始化完毕的槽。图像持有于 PSRAM，关闭时沿用原 UI 缓存分离与引用计数释放。没有开放任意文件系统路径或 LVGL 指针。

读取在 JS 工作线程初始化期间进行，不阻塞 UI 任务；共享 JS 工作线程在此期间暂不能执行其他应用回调。每帧不做文件 IO。图片内存约增加 3.55 MiB，不应称为零成本；真机验证需检查初始化预算、运行表现和关闭后的释放。

重建与上传：

加载器检查使用生产 C 实现与真实 QuickJS，包括权限、阶段、ID、文件路径、像素和尺寸、截断/多余字节、分配失败、读取期间关闭、资源数和 4 MiB 边界。Canvas 增加实际 LVGL 对 1620×385 图像的镜头偏移与 RGB565 裁剪像素检查。游戏同时检查高清加载成功和缺图回退场景。


真机结果：COM10 已刷入 0.42.0、安装游戏 0.3.0，两张背景加载成功；启动约 2 秒。实际首组战斗和音乐播放正常，运行时错误 0。关闭前后 PSRAM 可用量从约 19.8 MiB 恢复至约 24.6 MiB，上下文、控件、计时器与 JS 堆清零，再打开正常。证据见 `docs/brave-road-hq-results.json` 和 `.tools/diagnostics/brave-road-hq-combat/before-after.png`。
