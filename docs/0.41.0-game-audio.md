# Core 0.41.0：游戏 UI 与音频（Native API 43）

游戏 UI 采用 `page.json` 低频菜单 + 场景 Canvas + 缓存 HUD 的组合。示例是 `apps/brave-road`；共享 helper 是 `tools/app-shared/game-hud.js`。page 初始化创建对象，不能把 page 的使用等同于每帧重新解析 JSON。每帧大量对象更新的开销才需要通过 Canvas 批量提交减少。

## 新接口

```javascript
// Music 为 Ouse 的共享媒体目录；不要误写成 SD 根目录 /Music。
Ouse.media.play({path:'Music/brave-road-music1-v1.wav', loop:true});
// 单独的二进制资源，或音效银行中的偶数字节区间。
Ouse.media.effect({asset:'sounds', offset:0, length:9196, gain:85});
Ouse.media.pause();
Ouse.media.resume();
Ouse.media.stop();
```

`loop` 可省略，默认 false，必须是布尔值；支持 SD 和包内 WAV，不支持 HTTP 循环。每轮重新解析和解码完整 WAV，仍受原媒体任务的总超时限制。媒体所有权、焦点、暂停和取消沿用原服务。

`effect` 要求 `media` 能力、前台有效应用、属于当前应用实例的运行中媒体任务。音效为 PCM16LE / 单声道 / 16kHz，无 WAV 头；gain 为 0～100 整数。offset/length 必须是资源内的偶数字节区间，每次不超过 64,000 字节。最多 5 路，满时返回 false。接受后复制到 PSRAM，混入背景流，求和后限幅；暂停冻结音效，停止和任务结束清理副本。它不是一个可以独立启动声卡的通用音频流 API。

图片总解码预算从 128 KiB 调整到 512 KiB。BPK 总大小仍限 512 KiB、资源数仍限 16、图片单边仍限 512；长音乐通过 SD 读取，避免占据应用包。

## 验证

- `node tools/test-brave-road.cjs`：第一关数值、28 只怪物/6 波、技能限制、成长、受击前摇、拾取、绘制边界、HUD 缓存、音乐结束和生命周期。
- `python tools/test-ouse-services.py media wave`：5 路混音、资源复制、限幅、所有权、暂停、参数边界、完整 WAV 多轮解码与取消，以及既有媒体路径。
- `python tools/test-canvas-runtime.py`：真实 LVGL/QuickJS 渲染回归和像素比较，主机耗时不能当作面板 FPS。
- `python tools/test-ouse-app-packages.py --apps brave-road`：设备包解析、资源边界、QuickJS 编译与页面验证。
- ESP-IDF 生产构建通过，COM10 已刷入 Core 0.41.0。

第一关素材、数值的来源和仍未还原的行为见 `apps/brave-road/README.md`。恢复原版数值不等于战斗行为完全等价；没有以主机测试代替人工通关证明。

真机结果：首组 3 只怪物击败、24 次短音效接受，背景音乐消费进度超过 109 秒；跨过 90 秒原曲结尾仍输出、无媒体错误。场景 700 次提交对应 HUD 5 次提交。关闭后上下文、控件、计时器和 JS 堆全部归零，再开正常。证据：`docs/brave-road-device-results.json`，原始记录在 `.tools/diagnostics/brave-road-v2-verified2` 和 `brave-road-v2-loop`。没有把提交次数当作面板 FPS，也没有声称人工完整通关。
