# Core 0.26.0：光标、桌面排序与现有 C6 BLE 验证

## 输入框

在输入法公共绑定层配置 2 dp 插入线和 500 ms 闪烁周期，显式同步焦点，适用于系统原生设置和第三方 `textInput`。空字段、密码字段都显示光标；切换字段、失焦、退出应用或删除控件时清理旧焦点。光标随主题使用强调色；刷新不重复重启闪烁动画。不会改变密码保存规则或自动显示密码。

光标左边框对齐到文字插入点内侧，避免原生无内边距输入框将光标裁到控件外。真实 LVGL 像素测试验证空字段确实绘制及交替隐藏光标、浅深主题、有/无内边距及紧凑高度、文本插入位置、密码焦点转移和关闭清理，不仅检查样式属性。

## 桌面

长按图标后直接拖动，其他图标按插入位置顺移；原图标暂时隐藏，放大图标跟随手指。靠近左右边缘停留约 500 ms 翻页，可跨页移动；普通左右滑动仍限制一次一页。松手自动完成，不增加排序设置页或说明小字。拖到桌面之外松手则取消；整理期间不打开应用，应用启动或桌面重建会安全取消未完成的拖动。

顺序独立于应用注册表，以稳定应用 ID 保存，不受名称、语言、目录遍历顺序或更新注册位置影响。首次没有排序记录时设置默认在前，其他应用按 ID 确定性排序；启动恢复完成后补全排序。之后新应用追加末尾、更新保留位置、卸载后顺移并删除记录。设置应用也允许拖动。

元数据位于 `/bpkfs/launcher-order.v1`，只有原生存储入口可以写；第三方应用私有存储不能访问它。工作线程先写临时文件、flush/fsync、关闭，再原子替换旧文件，不在 UI 线程访问 Flash，不增加存储线程。保存失败显示可重试对话框，不假报成功；读取失败保留原文件，不静默覆盖。异步结果通过单飞邮箱交回 UI，保存期间再次整理不会被旧完成结果覆盖。

普通应用分区刷写和重启保留顺序；擦除整片 Flash、格式化或覆盖 LittleFS 数据分区不保留。元数据读取有 1 MiB 的损坏文件保护，这不是应用安装数量上限。

## BLE：只验证，不更新 C6

现有启动日志标识 ESP32-C6，并报告能力 `0x0d`：WLAN SDIO、BT HCI over SDIO、BLE only；当前 P4 固件正式的 NimBLE/Bluedroid 都保持关闭。因此“主机未启用蓝牙”不等于“C6 固件没有 BLE”。日志同时存在 Hosted 版本兼容警告，不能仅凭能力位宣称完整蓝牙接口或 HID 已可用。

新增受 MCP/设备调试开关控制的 `DBG_BLE`，仅在主机正式蓝牙栈关闭时编译：通过当前固定版本 Hosted 传输发送 HCI Read Local Version、LE Read Supported Features，设置短时被动扫描并在结束时关闭。没有任意 HCI 命令入口，没有配对、广播、绑定或第三方应用 API，不调用 OTA、Flash 更新或控制器重置。强接收处理器只在主动诊断期间解析结果，其余时间丢弃蓝牙事件。

这个诊断依赖当前 ESP-Hosted 2.12.3 的内部传输 ABI，升级依赖时必须重新检查；不能与未来正式蓝牙栈同时启用。即使 HCI 和扫描通过，HID 仍需后续实现主机栈、GATT/HID 服务、配对安全与绑定保存、实例资源管理、断线释放按键和 Wi-Fi/RAM 共存测试。本轮不开放这些能力。

## 离线验证

统一入口 `python tools/test-regression.py` 现在包括 20 项。新增：

- 真实 LVGL 长按插入、跨页拖动、越界取消、无误启动、失败重试、更新保位及卸载删除。
- 独立启动的保存顺序恢复、重复 ID 损坏记录拒绝与保护。
- 真实存储函数的临时文件读写、原子替换失败保留旧数据、内存不足、嵌入 NUL 和过大文件拒绝。
- HCI 接收解析的截断、非匹配、非活动事件以及版本/能力/状态/广播报告。
- 原生安装器的启动恢复通知确实经 UI 线程交接，失败的安装恢复不会触发排序提交。

统一 UI 也通过 AddressSanitizer。Flash 构建与真机结果另行记录，离线替身测试不代替硬件验收。

全量字体生成仍会被原有应用中源字体缺少的 U+51C7/U+9AB0 阻止；本轮没有修改这些应用。已单独检查新增桌面文案，其全部汉字都由现有 CJK 字体池覆盖。
