# 0.4.6：USB 安装 BPK

本版新增轻量核心自己的安装服务，保留 0.4.5 的桌面、主题、本地化、电源、音频和 C6 Wi-Fi。硬件串口、并发音频/Wi-Fi 和断电恢复仍需板上验收；电脑端测试使用真实安装器、LittleFS 之外的主机文件系统，以及真实 LVGL / QuickJS。

## 明早测试

1. 固件包中 `ouse-core-0.4.6-full.bin` 烧录到 **0x0**，DIO / 80MHz / DoNotChgBin。也可以在同分区布局的现有系统上，仅烧录 `ouse_core_desktop.bin` 到 **0x10000**，保留设置。
2. 正常启动，日志中应有 `DESKTOP READY`，随后 `OuseUSB: READY; UART0 115200; protocol=OPK1; storage=ready`。
3. **关闭下载工具、串口监视器及其他占用串口的软件**。使用板子的 CH343 USB/UART 接口、同一个 COM 端口。不是另一个原生 USB 插口。
4. 在固件包解压目录运行，COM10 换成实际端口：

```powershell
python bpk.py --port COM10 hello
python bpk.py --port COM10 install usb-counter.bpk --open
python bpk.py --port COM10 list
```

桌面增加 USB Counter，自动打开后可以加一、清零；与内置计数器是两个独立应用。返回桌面、从最近应用恢复、切换主题/语言/字号均可测试。正常重启后，应用图标应恢复。关闭最近应用只清理实例，不卸载软件。

再次安装相同 ID 会更新软件并关闭旧实例。卸载：

```powershell
python bpk.py --port COM10 remove user.usb-counter
```

包内提供 pyserial 3.5；若单独拷贝脚本，先安装 `python -m pip install "pyserial==3.5"`。脚本开串口前将 DTR/RTS 置为 false，不主动复位或进入下载模式；Windows USB 驱动本身的开口行为需实测。

## 服务如何后台运行

桌面成功创建后才启动 `ouse_installer` 独立任务，内部 RAM 栈 16KiB、优先级 3。UART 驱动通过硬件中断收字节进入环形缓冲；空闲任务阻塞在读取上，**没有 1ms 定时轮询或 Brookesia 共享调度器**。上传过程中最多每秒检查一次 30 秒无活动超时。

同一个任务拥有协议解析、接收缓冲、磁盘写入和包列表。只有应用检查/注册/关闭/桌面刷新通过 `ouse_core_post_ui` 交给 LVGL 任务，并等待其完成。Flash I/O 不在 UI 回调中。服务拒绝复用别人已安装的 UART0 驱动，以保证唯一 RX 所有者；控制台仅保留输出，不启动 REPL。

接收缓冲最多 70000 字节，放在 PSRAM。协议 OPK1 使用带随机会话标识、序号和 CRC32 的文本帧，512 字节分块、逐块确认；最后一个请求的重复包返回缓存响应，不重复执行写入、更新或卸载。电脑忽略启动日志和无关行。会话不活动 30 秒后丢弃未提交内容。

## 包、存储与兼容性

这里的 BPK 是 **Ouse Core format 1 / runtime API 1**，不是旧 Brookesia 安装协议或旧应用格式。旧音乐/文件管理器 BPK 需要迁移其 JSON/JS API，不能直接安装。

第一版支持 ZIP_STORED（不压缩）容器，严格只有三个文件：

```json
{
  "runtime": "ouse-core",
  "format": 1,
  "api": 1,
  "id": "user.usb-counter",
  "name": "USB Counter",
  "icon": "plus"
}
```

另两个文件是 `page.json`、`app.js`，各最多 32768 字节；清单最多 1024 字节。图标选 plus / test / monitor / music。ID 限 user.*、47 个 ASCII 字节，标题最多 47 个 UTF-8 字节。暂不支持包外文件、图片/音频资源、压缩 ZIP、ZIP64、模块导入或旧 BPK 插件。现有 dp/sp、主题、语言和设备 JS API 可以照常使用。图片仍可用于固件内置包。

打包自己的应用：

```powershell
python bpk.py pack usb-counter my-app.bpk
python bpk.py --port COM10 install my-app.bpk --open
```

修改样例的 manifest ID 和名称以安装独立应用。固件总容量目前为 8 个注册应用，含 4 个内置应用，所以可安装 **4 个**。达到上限时在写 Flash 前拒绝。

校验包含：ZIP 本地/中央目录一致性、大小、重复文件、目录穿越、符号链接、CRC、清单版本、页面结构、唯一控件 ID、尺寸边界、JS 语法。只编译 JS，安装时不执行应用代码。语法正确但运行出错的应用仍由运行时错误页和执行时间/内存预算处理。

安装目录是 LittleFS 的 `/ouse-v1/`，只加载此目录内新格式的 user.* 包。完整烧录文件不覆盖 0x810000 起的 LittleFS，也不加载旧应用。服务首先正常挂载；只有**整个分区完全是 0xFF** 时自动初始化。非空分区挂载失败会保留数据并报告 storage=unavailable，不自动格式化。

写入先经过内存校验，再写临时文件、同步，最后用 LittleFS 原子 rename 替换正式文件。掉电发生在提交前保留旧包，发生在提交后重启恢复新包；启动忽略并清理遗留临时文件。更新前清理最近应用借用的预览，再关闭旧 JS/控件/定时器，防止悬空引用。若提交后 UI 队列因资源不足拒绝刷新，文件已保存，重启可恢复，不能把这种异常报告当成成功更新。

## 验证范围

`tools/test-ouse-runtime.py` 使用真正 LVGL 9.5 / QuickJS-NG 0.14，包含主机串口替身驱动真正 C 安装器的端到端测试：拆帧、坏 CRC、超长输入、丢 ACK 重试、坏 ZIP/路径/版本/页面/脚本、热更新、容量上限、传输断开、超时、重新启动恢复、卸载及 JS 清理。固件固定 ESP-IDF 6.1.0，不升级依赖版本；新增 LittleFS 1.22.3。

需要实机补测：串口独占、保持桌面操作时上传、打开应用时覆盖更新、Wi-Fi 开启时安装、上传中拔线/复位、重启恢复和卸载恢复。不要同时使用串口监视器与安装工具。
