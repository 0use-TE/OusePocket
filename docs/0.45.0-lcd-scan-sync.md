# 0.45.0 — ST7796 scan-feedback port from ILI9341_T4

Reference: https://github.com/vindar/ILI9341_T4 at
`bee2957aefe6aa443f21da96b0856b0e1746e696`.
The pre-port software recovery point is `b97d392` (Core 0.44.2).

The upstream differential engine is included unchanged, with its LGPL license,
in `boards/waveshare_lcd35/t4diff/`. This is not a direct build of the Teensy
driver: ST7796 initialization, P4 SPI/DMA, FT6336 touch and RTOS integration
remain board-specific. There is no dependency on an Arduino firmware runtime.

| Upstream mechanism | ESP32-P4 adaptation |
| --- | --- |
| DiffBuffTemplate: exact changed spans, gap merging and bounded overflow fallback | Same source, instantiated at 320x480, 6-pixel gap, 8 KiB log |
| Portrait canonical mirror and rotated incoming images | Same rotation=1 conversion; landscape sends vertical logical strips in physical scan order |
| `_getScanLine` / refresh-period sampling | ST7796 `0x45`, GPIO22 MISO, 1 MHz reads, verified dummy-bit decoding, measured physical line count including porches |
| `_updateAsync`, spacing=2, scanline-trailing `readDiff` waits | Background task follows the same wait/continue protocol, strict phase entry and two-cycle minimum spacing |
| DMA completion interrupts and timer callbacks | ESP-IDF panel DMA plus task sleep/short bounded microsecond waits; no LVGL calls from sender |
| Scan position estimated between hardware reads | Validated paired reads per frame; calibrated line period drives within-frame predictions |
| Update margin / missed scan deadlines | `late`, `unsynced`, `invalid`, `pixels`, `empty` counters in OuseLCDSync logs |

The previous always-full-frame sender is only the allocation-failure fallback.
Empty diffs send nothing. Failed transfers invalidate the mirror and force the
next update to repaint all pixels. Invalid feedback is rejected, transmission
can continue unsynchronized, and calibration retries after two seconds. A late
transfer is completed rather than leaving an incomplete image; it is explicitly
counted and is not claimed to be tear free.

Physical GSCAN counters are not logical LVGL y coordinates. Calibration checks
every adjacent sample and wrap, rejects the whole calibration on incoherence,
and does not silently filter anomalies. Extra porch lines are conservatively
treated as preceding the visible image for waits, but following it for write
deadlines. The ILI9341 refresh-rate register values are not copied to ST7796.
ST7796 FRMCTR1 is set to FRS=9, DIVA=0, RTNA=31 (nominally near 50Hz), then
the actual timing is measured rather than assuming the nominal frequency.
This corresponds to the upstream recommendation to tune refresh rate for
spacing=2, leaving transmission headroom and approaching a 25 FPS cadence.

The existing UI-compose / pending / sending snapshots still isolate UI from
SPI waits and permit replacing an obsolete pending frame. The upstream mirror
adds 307200 bytes of PSRAM; its diff log adds 8192 bytes. Existing DMA bounce
buffers are reused. Orientation changes drain active DMA, invalidate the old
epoch and canonical mirror, then repaint the new orientation.

Validation:

- `python tools/test-lcd-async.py`: production ownership and fallback path,
  LCD-only MISO/sample-point changes, 1 MHz reads and 80 MHz clock restoration
  on success/failure, callbacks, orientation, allocation failures and DMA drain.
- `python tools/test-lcd-scan-sync.py`: actual upstream engine and production
  scheduler against a timed SPI/scan model; full/sparse/empty updates, portrait
  and landscape pixels, diff overflow, corrupted/unavailable feedback, recovery
  repaint, and observable deadline misses when transfers are too slow.
- ESP-IDF 6.1 firmware build; only the application partition is updated, retaining
  existing user storage. Device artifacts live in `dist/firmware/lcd-t4-0450/`.

Host simulation and successful boot do not establish optical tear-free output.
Physical tearing, rotation mapping and responsiveness require viewing the real
panel. User-driven page turns remain the visual acceptance step.

Device result (2026-10-21): application partition flashed and hash-verified;
running ELF SHA256 matches the frozen build. Measured `lines=484`,
`line_ns=40948`, `period_us=19818` (~50.46 Hz), spacing=2. Final startup sample:
188 frames, 188 scan-synchronized, 0 unsynchronized, 2 conservative deadline
misses, 0 invalid feedback samples, 518109 pixels transmitted, 5 empty diffs.
No SPI send errors or startup panic; runtime errors=0 and heap check `ok=1`.
These are boot-phase counters, not a game/scrolling optical acceptance test.
Exact binary hash, UART evidence paths and runtime checks are recorded in
`dist/firmware/lcd-t4-0450/manifest.json`.
