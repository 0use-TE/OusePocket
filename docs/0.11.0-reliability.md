# 0.11.0 核心可靠性

本轮补充服务健康快照、Wi-Fi 有限恢复、原生后台活动入口、安全重启收尾及卸载中断恢复。系统核心、工作任务与驱动仍为原生，底层仍用 FreeRTOS；不增加音乐/闹钟业务 BPK，不开放外设。核心 C API 10，JS API 1。验证与产物记录在 STATUS 顶部；本版不自动烧录。

## 服务和后台活动

原生设置新增“后台活动与服务”。展示 Wi-Fi、音频、存储、设置保存、HTTP 网络、闹钟和安装器状态；状态为 starting/ready/degraded/recovering/unavailable。当前实现根据服务已发布的就绪/错误和任务记录构成快照，**不是工作任务心跳监控，也不能自动检测所有死锁**。某次请求失败不一定意味着网络工作任务已损坏；网络传输错误仍以具体任务为准。

一个原生协调任务，12 KiB 栈、优先级 2，每 500 ms 复制缓存并扫描有界任务记录，最多展示 12 项活动，保留总数并明确截断。不做文件、驱动或 JS 调用。快照含正在进行的原生请求（包括前台提交和不可取消提交），以及显式 JS 后台许可；活动不等同于常驻通知，也不等同于应用实例仍存活。oldestMs 是请求经过时间，不是 CPU 时间或卡死判断。

“停止”只提交请求，原生任务实际收尾前继续显示 stopping；不可取消提交禁用停止。结束后台脚本只撤销指定实例的后台许可：保留实例，挂起时冻结计时器/回调，不停止独立原生媒体。请求在 JS 工作者处理，实例 ID 不复用，旧活动不会结束重新打开实例的后台许可。媒体等独立活动需另外停止。系统闹铃停止走原生 dismiss，不会因只取消音频任务而在下一轮立即重响；不删除未来闹钟。

```js
const health = Ouse.system.health();
// available, phase, blocker, quiescing, sampledMs,
// systemActivitiesTotal, activitiesTruncated,
// services: [{name,state,error,active,oldestMs}]
const activities = Ouse.system.activities();
// 仅当前 app ID 的可见缓存项；可含旧实例留下的原生工作。
// [{taskId,instanceId,kind:'native'|'javascript',reason,cancellable,stopping}]
const accepted = Ouse.system.stopActivity(taskId);
// 严格正整数 ID，仅允许停止同 app ID 的原生任务。
// 其他应用返回 false；不提供 JS 重启系统、任意停止其他应用权限。
Ouse.background.end(); // 本实例结束后台许可，既有接口
```

activitiesTruncated 表示全系统缓存截断；需要完整本应用任务时仍用 Ouse.tasks.list。停止接受不等于完成，最终以 tasks.get/onComplete 为准。预览返回 available=false、phase=preview、空活动，不伪造真实服务健康或系统操作。

## Wi-Fi 恢复

扫描/断开/禁用停止事件未到时仍隔离旧请求。等待 5 秒后只尝试一次 esp_wifi_stop，升级到等待 STA_STOP；再次等待 5 秒后仍未确认则报告 recovery_failed、服务不可用，旧任务保持非终态并拒绝新操作。即使恢复 RPC 返回 NOT_STARTED，也只确认硬件关闭，不代表旧事件队列已排空，因此仍等待 STA_STOP。迟到的 STOP 可安全解除屏障，原任务按真实超时/错误结束；下一次显式请求才启动新站点操作。

不强删工作任务，不在未知硬件状态下重用请求，不循环重置 C6；RPC 自身仍受固定驱动的超时机制约束，不能宣称 5 秒内必然从 RPC 返回。运输层明确 down 仍沿用原有处理。没有实现所有驱动的通用自动重建，也没有强制重启整机掩盖故障。

## 安全重启协议

仅原生设置提供确认入口。开始后关闭新应用/任务提交的入口，结束脚本应用实例，取消可取消的网络/音频工作，并通知 Wi-Fi 工作者请求整站停止。已接受的存储、闹钟、设置与包提交继续安全完成，包括尚在排队的提交，不因关闭应用而丢弃；短设置提交有计数保护，避免提交与关闭入口之间的竞态。关闭回调中新提交的工作会被拒绝，因此应用应在正常运行期间保存数据。

协调器等待：UI 关闭完成、JS 上下文释放、原生活动终态、安装器当前操作结束且无待恢复卸载、存储队列/维护操作完成、闹钟停止调度并确认、Wi-Fi 实际停止，以及设置落盘。只取消任务不会被当作实际停止。收尾期间发生的存储修改/闹钟提交错误会阻止本次重启；设置保存错误也会阻止。满足条件后再观察至少 500 ms，然后调用 esp_restart。

整个等待期限 15 秒。超时进入 blocked，显示 blocker，保留关闭入口状态，**不强制重启或格式化**。可重试安全重启；或者在 UI 关闭回调已返回后选择恢复使用。恢复使用不重建已关闭应用、不撤销已完成的取消；Wi-Fi 配置保留，已停止连接需显式重新连接。UI 派发上下文固定保存，超时后迟到回调不会引用已释放的栈。

这是运行中软件重启协议；不承诺外部拔电可收尾，不实现 PMIC 断电、深睡或 RTC 唤醒。系统服务本身已经完全卡死时，只能诊断被阻塞，不承诺自动修复。

## 卸载中断恢复

安装器单线程持有一条持久卸载意图 `/bpkfs/ouse-apps/remove.pending`。固定 64 字节 v1 格式、app ID 和 CRC32，小端校验字段；临时文件 flush/fsync 后原子 rename。意图提交成功是卸载决定的提交点，之前失败保留原应用。

提交后依次关闭应用、撤销闹钟触发资格、删除包文件、等待媒体实际停止、FIFO 清理闹钟和私有数据；全部成功才删除意图。每一步可重复。失败保留意图，禁止新安装，允许同一 app ID 重试 REMOVE，即使包已删除、UI 注册已消失。

重启挂载后先读取意图，再恢复包；待卸载包不会被重新激活或恢复闹钟授权。启动原生闹钟后继续完成清理。CRC/格式损坏时保存原文件，停止包恢复和新安装，诊断安装器错误；不猜测应删除哪个 app。闹钟文件本身损坏导致清理失败时也保留意图，需要维护处理。本轮不提供一键抹除损坏数据库，也不把任意 Flash 损坏称为可恢复。

## 内存口径与开销

Ouse.system.info 新增 internalLargest/psramLargest（各内存域最大连续空闲块）、internalMinimum/psramMinimum（本次启动历史最低空闲字节）和 memorySampledMs。协调任务名义每秒一次采样，缓存 4 个数和时间；最大块查询可能遍历堆，因此放在原生协调任务，UI/JS 查询只复制这组缓存。时间为 0 表示尚未采样，不把初值 0 当作内存耗尽。数值不是某个应用的独占内存，也不是可分配成功承诺。

维持原 QuickJS 预算、分配公平性和经过时间紧急保护；本轮不提高脚本阈值。尚未加入全任务栈监测、动态内存压力回收、安全启动模式或固件 OTA 回滚。这些不属于“外设尚未开放”，因此不能宣称除硬件外所有内核能力已完成。

## 验证边界

相关主机检查使用真实任务登记、协调循环、卸载意图文件与清理函数、QuickJS 绑定、Wi-Fi/闹钟实现；RTOS、TLS、驱动和 UI 采用确定性替身。验证提交关闭、取消/实际完成、收尾等待/超时/迟到 UI/恢复使用、外应用隔离、CRC/提交失败及各清理阶段重试。分类 service-test BPK 增加健康与活动查询及停止本应用原生任务。主机检查不能替代设备上的调度、RPC、断电时序和原生页面视觉验收。
