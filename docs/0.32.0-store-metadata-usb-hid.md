# 0.32.0 商店元数据与 USB/BLE 检查

网页使用包内真实图标，按分类、名称/作者/介绍搜索、最近更新/名称/体积排序；发布位于独立 `/publish` 栏目。选择 BPK 后在浏览器本地解析清单与 OIC1，自动填表；最终发布仍由服务器严格校验包结构和元数据。修改的介绍、作者、发布日期、版本和最低 API 写回最终下载的 BPK；包的 SHA256 随之重新生成。商店首次上架与更新时间由服务端维护，首次上架时间更新时保留。

manifest.json 可声明 description（非空，最多 512 UTF-8 字节）、author（非空，最多 64 UTF-8 字节）、releasedAt（有效日历日期 YYYY-MM-DD）。内核拒绝错误类型、NUL、超长文本及无效日期。解析元数据与应用管理快照均在 PSRAM。`Ouse.packages.list()` 每项增加同名属性；商店详情展示作者与日期。作者是自述元数据，不是发布者身份认证。原生 API 36，JS API 1。

USB 音频使用 P4 原生 OTG HS、TinyUSB UAC2、ES8311/I2S 唯一音频工作线程；蓝牙 HID 使用 C6 控制器、ESP-Hosted HCI 和 P4 NimBLE/GATT。HID 会话的互斥范围是蓝牙应用，不占用音频 codec，不关闭 USB。两者共享 CPU、内存和任务注册表，应以并发实测确认调度及余量。

BLE HID 没有 A2DP 音频流；计算机把声音交给 USB 音频端点，BLE 只发送按键/鼠标/媒体控制。HID 音量、静音、播放暂停会改变电脑播放行为，不能把这种正常控制误判为接口冲突。

验证：29 项主机回归、4 项服务端测试通过；原生 BPK 测试新增 8 个超长/类型/NUL/无效日期拒绝样例。Next.js 生产构建通过；TinyUSB OUT/feedback 回归和 FS/HS 双向 UAC2 描述符检查通过。浏览器实测图标、分类、上传自动填表和发布成功，下载包内元数据与表单一致。

COM10 已仅烧录 P4 应用区至 0.32.0，未更新 C6。记事本经 HTTP 更新至带元数据的 1.1.0，作者与日期显示正常，原笔记保留；堆检查正常、运行错误 0，商店前台内部空闲 147,715 字节。现场 BLE connected/encrypted/bonded 均为 1，但 USB mounted=0、speaker=0、microphone=0，Windows 无 Ouse 音频端点。已请求接入原生 USB OTG 数据线；此状态下无法确认 USB 音频与 BLE HID 的完整并发实测，不能把资源检查/单项回归作为并发通过。
