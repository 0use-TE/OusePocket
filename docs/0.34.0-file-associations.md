# 0.34.0 默认文件应用

Native API 38 增加 `Ouse.files.open(path)` 与 `Ouse.files.onOpen(handler)`。前者需要 `sdcard` 能力及前台身份，返回值仅表示请求已排队。系统再次核对前台来源、SD 路径和当前安装的处理应用。路径采用 SD 根形式，例如 `/Ouse/Pictures/example.jpg`，最多 127 UTF-8 字节；超限拒绝，不截断。BPK 使用系统安装器，不参与默认关联。

manifest `fileTypes` 可声明 `image/jpeg`、`audio/wav`、`video/x-msvideo`，不重复、最多三项，最低 API 38。JPEG/AVI 要求 `photos`，WAV 要求 `media` 与 `files`。固件、打包器和云端均校验。目标应用注册 `Ouse.files.onOpen(event => ...)` 接收 `event.path`；冷启动与已有实例均由脚本工作线程递送，UI 线程不执行 JavaScript。未处理路径保留一份，新请求替换旧请求，实例关闭后不递送。

唯一处理应用直接打开；多个时先选应用，再选“仅此次/始终”。候选分页，每页最多八个，不限制应用安装数。设置首页“默认应用”可设置或清除 JPEG/WAV/AVI 关联。关联按应用 ID 保存，卸载或不再支持该格式时自动清理。选择“每次询问”但只有一个处理应用时仍直接打开。

偏好由存储线程写入 `/bpkfs/file-defaults.v1`：暂存、flush/fsync、原子替换，独立于桌面排序及应用私有数据。完成回调通过原子标志交接，失败有系统提示。SD 不可用时不启动读取；只读支持整个 SD，下载和写入路径限制不变。

资源管理器调用系统打开 JPEG/WAV/AVI，其他文件继续显示详情。相册等待旧任务取消后加载外部路径；音乐等待曲库恢复后播放。现有解码器验证 JPEG、PCM WAV、MJPEG AVI 内容，不宣称支持 PNG、MP3、MP4。共享删除仍受权限控制。

测试覆盖默认持久化、唯一/多个处理应用、仅此次/始终、卸载清理、前台与路径边界、相册取消交接、音乐冷/热启动与缺卡处理。桌面编辑模式仍为所有可卸载应用显示叉号，内置设置不显示。
