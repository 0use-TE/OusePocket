# 原生应用打开动画

桌面点击应用时，图标轻微收缩，纯色圆角背景从图标位置展开到应用内容区，图标移动到内容区中央并放大；首屏准备好后，背景与图标淡出，露出应用。状态栏、手势条或三键导航继续保留。

冷启动：24 ms 按下反馈包含在 180 ms 展开阶段内，之后约 60 ms 淡出。后台实例从桌面恢复时使用 120 ms 展开和 48 ms 淡出。实际时间受 16 ms UI 调度、绘制和 SPI 传输影响。慢加载时，完整背景和中央图标停留等待，等待期间不重复重绘静止画面。

脚本工作线程在过渡期间正常执行。原生同步 `open()` 可能占用 UI 线程创建大量控件，因此在回调返回后起算可见动画时间，避免加载耗时跳过展开；动画时长不包含这部分同步创建时间。脚本运行时在管理器 root 上设置内部 `OUSE_APP_LOADING_FLAG`，只有第一次控件构建与样式应用完成，或故障页已建立，才清除该标志。动画等待这个信号，不把 `open()` 返回或异步 JS 初始化返回当作首屏已经显示。

主要实现位于 `components/ouse_core/ouse_launch.inc`，桌面入口位于 `ouse_core.c`，首屏握手位于 `components/ouse_runtime/ouse_runtime.c`。程序调用 `ouse_app_open()` 和最近应用恢复保持原有入口；从桌面恢复后台实例使用短动画。调试状态增加 `launching` 字段，便于真机观测。

## 资源和中断

- 不截取或缩放整个应用页面，不实时模糊背景。只有最大约 64 dp 的图标使用缩放图层，背景使用普通矩形填充。
- BPK 图标像素复制到有界 PSRAM 缓冲；先删除动画图像与缓存，再释放副本。动画不借用安装包被替换后可能失效的图标像素。
- 动画期间重复点击不重复创建应用。边缘返回、底部操作、Home、应用关闭/切换、主题/语言或桌面重建、熄屏、低内存和系统对话框会结束或取消过渡。
- 低内存时跳过装饰动画，正常打开应用。打开失败立即撤罩并展示原生错误提示；慢启动最多等待八秒，然后撤罩并提供返回桌面重试的提示。
- 动画结束后删除临时对象、定时器、图标副本和源图标删除监听，恢复源图标及桌面/应用容器显示状态。

## 远程烧录

设备移到家中后，本机 COM10 消失；按用户提供的 SSH 入口连接远端 Windows，识别到 COM5 的 CH343，设备序列号与之前一致。使用远端已有 Python/esptool，在独立临时目录校验上传固件哈希并只写 `0x10000` 应用区；保留 NVS、LittleFS、BPK 和 C6 固件。

最终镜像写入哈希校验通过，启动 ELF 指纹匹配本次构建。通过实际桌面指针点击，设置与已安装的计算器分别完成冷启动和后台恢复，共四项真机验证；捕获到 `launching=true` 并最终变为 `false`，应用首屏控件可见。已查看设置中央图标和计算器展开中间帧。堆完整性 `ok=1`，无 panic 或意外重启。

测试阶段修正了两类主机验证问题：调试控件树的节点上限使第三页的待办无法被该工具定位，因此改测首页计算器；注入松手事件确认后仍需要等 LVGL 分发点击，再读取前台状态。先前失败记录保留，没有将其计为通过。真机还发现原生设置同步构建会挤掉动画时间，修正计时后重新构建、重刷并验证，最终镜像为上面的 AF348C… 哈希。

31 个安装包 ID 与烧录前一致，验收前后保留三键导航、中文和 100% 字号。验收期间观察到主题从早期快照的深色改为浅色，最终保留最新浅色设置，没有覆盖为旧快照。最后关闭测试实例并回到桌面，`live=0`、`launching=false`，串口关闭且没有残留触摸。
