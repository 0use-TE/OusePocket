# 0.18.0 SD 资源管理器

## 用户功能

`user.explorer`（资源管理器）直接从 SD 卡根目录开始浏览，不局限于 `/Ouse`，也显示隐藏名称的文件和目录。支持进入任意可访问子目录、返回上级、刷新、每页八项、上一页/下一页以及文件大小和路径详情。列表按文件系统原有顺序枚举，不进行全卡扫描或一次性加载目录。

未插卡时自动弹出提示；已识别但无法挂载时显示单独的错误，不自动格式化。拔卡后清空列表并停止当前浏览请求。暂不支持插卡自动重新挂载，重新插入后需要重启设备。

第一版只读：没有删除、格式化、移动、重命名或文件内容预览功能。内部 Flash 完全不显示，应用安装及内部空间仍归应用管理。大于路径预算或无法取得信息的条目仍显示名称，但不能进入。单路径最多 1023 个 UTF-8 字节；返回名称受底层 FatFs/dirent 长度限制。

## 内核接口与边界

清单新增 `capabilities.sdcard: true`，只授予整张 SD 卡的只读目录元数据浏览，不扩大已有 `files` 权限。旧音乐/下载服务仍只能访问 `/Ouse` 下的受限目录，资源管理器没有网络或写入权限。

- `Ouse.files.browse("/", 0)`：提交原生 `storage/sd.browse` 任务，返回任务 ID 或 false；offset 为跳过的条目数，每次最多返回八项。
- `Ouse.files.directory(id)`：仅查询本应用实例的缓存，返回 `{path, offset, pending, more, error, entries}`；没有权限或记录不存在返回 null。
- entries 包含 `{name, path, bytes, directory, accessible}`。
- `Ouse.files.get()` 新增 `detected`，区分没有卡与已识别但文件系统不可用。

枚举、文件信息查询都在独立原生工作任务执行，不在 JS/UI 线程执行，也不会排在长时间网络下载后面。6144 字节工作栈、工作结果和目录页缓冲均使用 PSRAM；缓存按应用实例隔离，关闭/故障时释放，停止未完成任务。单次目录枚举预算五秒，队列最多四个请求；同一实例同时最多一个请求。路径固定挂在 `/sdcard`，拒绝相对路径、空组件、点目录、反斜杠、盘符及尾部点/空格，无法访问内部 Flash。

## 验证

- `node tools/test-explorer.cjs`：无卡弹窗、坏卡提示、根目录之外的 Ouse 同级目录、隐藏文件、分页、文件详情、目录错误、拔卡与过期回复、中文文本预算。
- `python tools/test-ouse-files.py`：现有文件写入、CRC、下载失败/取消与格式化边界回归。
- `python tools/test-sd-browser.py`：实际 C 枚举器的分页、根路径、隐藏文件、应用实例隔离、关闭/取消、I/O 错误、截止时间和路径越界拒绝。
- `python tools/test-ouse-app-packages.py --apps explorer alarm service-test`：重新打包当前源码，用原生 BPK 解析器、QuickJS 编译器和生产节点 schema 验证包与权限。音乐应用由另一会话修改，本次不覆盖或安装其工作中代码。

版本为 Core 0.18.0 / C API 19 / JS API 1。此版本不进行音乐传输或额外格式化。
