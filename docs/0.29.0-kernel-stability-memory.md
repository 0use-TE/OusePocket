# 0.29.0 内核稳定性与内部 RAM

## 0.29.1 闹钟缓存增量

仅将闹钟服务的 `db` 和 `cache` 两份普通数据库迁入外部 BSS，每份 8,264 字节，合计减少 16,528 字节内部常驻数据。`cache_lock`、任务队列、线程栈及提醒控制仍保留原位置，磁盘格式和逻辑不变。原生 API 32、JS API 1 不变。

闹钟生产代码主机回归与内核回归通过，包含持久化失败回滚、重复提醒去重、错过/稍后提醒、取消和卸载清理。IDF 构建通过；链接符号确认 `cache=0x48530ce0`、`db=0x48532d28`，大小各 `0x2048`，均落入 PSRAM。本轮不打断正在运行的设备烧录，实际内部空闲增量需更新固件后测量。

## 根因与修复

- 录音机实测一次正常定时回调耗用 13,747 μs，旧的 12,000 μs 硬限制把它当成死循环中止；当时 SD 仍 mounted/ready，并无分配失败证据。现在区分软调度片和硬异常阈值。前台/后台软片仍 12/4 ms，硬 CPU 上限改为 50/20 ms；初始化 100 ms 软片、250 ms 硬限。墙钟紧急保护仍 1/2 秒，不取消死循环防护，也不鼓励同步阻塞 I/O。
- 蓝牙持有者匹配原来允许零 session。应用暂停/内核清理/应用回调多次 close 时，第二次把 retiring ID 覆盖成零，产生永远无法结束的原生任务。现在零会话不匹配，关闭幂等，同主同模式重复 open 复用任务，已占用时不创建无用任务。
- 设置连续修改可能覆盖尚未结束的 devicesSave 任务 ID。现在合并到同一在途任务，版本匹配后才完成，忽略过时/重复完成通知。
- 蓝牙 JS 快照区分租约、全局占用、释放中、物理连接与三个 HID 报告的真实就绪状态。网易云不再把所有失败都称为占用，不在仅得到租约时伪装为已连接。
- 录音机不再每 250 ms 对整页条目重复格式化日期和刷新控件；录音时长与按钮状态继续更新，内容或交互状态改变时再渲染列表。插卡恢复沿用已有挂载检测与恢复接口，不格式化 SD。

## 内存分布

链接映射验证以下普通缓存位于 PSRAM 外部 BSS（0x485...）：

| 数据 | 字节 |
| --- | ---: |
| 原生任务注册表 | 22,160 |
| 通知正文记录 | 21,312 |
| 通知待打开记录 | 2,944 |
| 运行时诊断快照 | 2,224 |
| 合计 | 48,640 |

JS 工作线程内部栈由 64 KiB 缩为 32 KiB，QuickJS 栈保护由 40 KiB 调整为 20 KiB，给原生调用保留余量。加上缓存迁移，固定内部内存需求减少约 81,408 字节。任务注册表自旋锁、通知静态互斥量保留在内部 RAM。

没有把所有线程栈迁到 PSRAM：NVS/Flash 操作、DMA 与中断路径仍需要遵守 SDK 的内存约束。缩栈需结合实机栈水位和递归保护验证，不能仅因启用了 PSRAM XIP 就假定所有原生调用安全。

## 验证

离线统一回归入口 `python tools/test-regression.py` 最终 25 项通过，新增软片/硬限边界、反复 close、重复 open、认证/订阅/挂起状态、设置保存合并与过时完成测试；网易云连接状态及录音机静态列表不重复渲染另有 Node 测试。LVGL 主机夹具另运行 ASAN 通过。额外运行的历史独立入口 `tools/test-ouse-devices.py` 仍因缺少 `ouse_tasks.h` 夹具无法编译，未纳入统一回归；本轮设备服务生产代码由 kernel/services 入口验证，不把该旧入口报为通过。

P4 使用 COM10，只写入 0x10000 应用区，未修改 C6、NVS、分区表或 SD。固件 SHA-256：`85456b1ba48bc01aaca96f687e6e20b9f5a2a7c44cc954cd3c9f73ea5b98a239`。

实机详细记录位于 `.tools/stability-0290-result.log`、`.tools/stability-0290-serial.log`。本轮不等同于长期运行验收，真实拔插/硬件断电与所有第三方应用组合仍有验证边界。

本轮实机已验证：

- 同为相册＋录音机两个上下文、86 个控件，内部空闲从诊断时的 48,043 字节增加到 133,231 字节，最大连续块从 30,708 增至 88,052 字节。并非完全一致的网络/运行时历史，实际增量还包含清除旧孤儿任务等差异；固定内存减少量以链接布局和栈配置为准。
- 录音机连续前台运行两分钟，12 次采样均 errors=0，内部空闲稳定约 138 KB，没有原先十秒左右复现的误超时。普通应用路径 JS 工作线程栈最低剩余 24,948 字节。
- 网易云连续打开/关闭 15 轮后无 JS 实例残留，任务快照中活动蓝牙会话/设置保存任务为零；连续改音量 30 次并恢复原音量后仍为零。
- SD 安全卸载后录音机提示插卡，显式恢复后 mounted/ready 回到 1，原有四条录音列表恢复，无需重启或格式化。这不代替真实带电拔插测试。
- 临时应用无限递归被 QuickJS `RangeError` 拦住，线程栈最低剩余 7,984 字节；无限循环在 50,368 μs 调度 CPU 时间触发 50,000 μs 硬限，仅停止该应用，串口与系统仍响应。检查点有采样开销，因此不是精确 50 ms 的硬实时截止。堆完整性检查均 ok=1，测试包已卸载；诊断 errors=1 是这次故意制造的死循环记录，不是普通应用回退。
- 蓝牙关闭时网易云显示“请先开启蓝牙”，开启并恢复既有配对后显示“已连接”，未发送媒体控制按键；相机预览、相册、网络分析、接口测试、录音机逐一打开/关闭，无新增故障，最终 SD 与 BLE 正常。另见 `.tools/stability-0290-extra.log` 与 `.tools/stability-0290-final.log`。
- 最后正常应用启动复核：重启后 31 个用户包保留，临时测试包不在列表，errors=0、SD ready、BLE 既有绑定自动连接、堆检查 ok=1。尚未创建 JS 工作线程的冷桌面内部空闲 180,283 字节、最大连续块 139,252 字节；此值不可与已创建线程/运行应用的 133 KB 直接比较。见 `.tools/stability-0290-reboot.log`。COM10 已释放。
