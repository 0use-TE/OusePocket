# 0.45.2 — internal RAM recovery and system UI cadence

The user identified desktop paging and system operations as the remaining
performance issue. Preserve the visually accepted 0.45.1 scan synchronization.
The board-specific LVGL refresh timer now runs every 20ms instead of 33ms,
matching the measured approximately 50Hz scan period. This changes scheduling;
it is not a measurement or promise of 50 complete visible frames per second.
Full-screen SPI transmission still takes approximately 32ms before entry waits.
Desktop animation smoothness and input latency require user acceptance.

The resource monitor previously displayed internal RAM in MiB: 0.05 MiB means
approximately 50 KiB, not 0.05 KB. Version 1.0.1 displays internal RAM in KiB.

| Internal display allocation | 0.45.1 bytes | 0.45.2 bytes |
| --- | ---: | ---: |
| LVGL drawing buffers | 51,200 | 12,800 |
| Sender DMA buffers | 38,400 | 25,600 |
| Total | 89,600 | 38,400 |

This recovers exactly 51,200 bytes (50 KiB). LVGL uses one 20-line internal
buffer because pixels are copied to the compositor before flush completion.
Background DMA owns separate buffers. The original synchronous BSP fallback
still waits for DMA completion. Both sender buffers now hold 320 by 20 RGB565
pixels; wide partial rectangles adapt their row count to fit. Full landscape
frames retain the same 24 strips and all existing ownership/drain protections.
The three PSRAM snapshots, scan-entry conditions and worker stacks are retained.

Validation completed on 2026-10-21:

- Display flush-wake and bounded scan-window/production sender tests passed,
  including a 480 by 60 partial rectangle split across five DMA transactions.
- Resource-monitor package/schema/QuickJS validation and the IDF build passed.
- COM10 application-only flashing, flash hash and running ELF hash verified;
  normal boot reports core 0.45.2. Resource monitor 1.0.1 installed successfully.
- Identical 32-sprite shared-runtime probes measured 25.08 FPS before and after.
  The game limit remains 25 FPS; this test establishes no game FPS improvement.
  P95 callback gaps were 40/41ms, maximum 45ms, with no gaps above 60ms.
- During that probe, internal free RAM increased from 47,775 to 112,432 bytes
  (46.7 to 109.8 KiB). Largest free blocks increased from 30,708 to 69,620 bytes.
  Runtime errors were zero. The measured gain includes different cache/task
  state after reboot; only 50 KiB is attributed to the display allocations.
- Final resource-monitor check: 107,392 bytes free (104.9 KiB), largest block
  64,500 bytes, runtime errors zero and heap check `ok=1`. Its RAM row lies below
  the initial visible viewport, so no on-screen text assertion was made.
