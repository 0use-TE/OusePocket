# 0.16.1 底部输入隔离与 SD 卡识别

## 本轮范围

- 手势模式的底部 36 dp 导航起点区域使用透明、不可滚动的独立输入层。按下即由系统命中，不再等待位移超过阈值后才拦截应用；短滑取消也不向应用补发输入。应用内容区域开始的滚动保持原状。三键模式隐藏该输入层。
- 图片应用图标统一放入四分之一边长圆角的裁切容器，保持比例和透明度，适用于桌面、最近应用及通知。音乐、闹钟不再使用方形外轮廓。
- SD 卡仅在启动时识别并试读首扇区。没有挂载文件系统、格式化、创建目录或写入用户扇区，也没有扫描或输出用户文件内容。

## SD 实现

Waveshare 板使用 SDMMC slot 0、四线、20 MHz 和 LDO4，按板级 BSP 的连接配置初始化。探测在桌面启动后、Wi-Fi 服务创建前执行，避免两个插槽首次创建共享控制器的竞态。Wi-Fi 仍使用 slot 1；失败时只释放本次的 slot 0 和供电句柄，不调用全局 host deinit。

`ouse_sd_get()` 复制缓存状态：probing、detected、readable、capacity_bytes、sector_bytes、name、error。detected 表示卡初始化成功，readable 表示首扇区试读成功，都不表示文件系统已可用。512 字节 DMA 对齐缓冲在读取后释放；探测失败发布系统通知。

设置 → 系统信息 → 关于设备的配置区显示 SD 卡状态；串口调试 `DBG_SD` 可读取同一快照。当前不提供 JS 文件接口、下载、SD 安装应用、插拔实时检测或手动重试；拔卡后缓存不会自动刷新，后续阶段需要完整介质生命周期管理。

## 验证

`python tools/test-ouse-sd.py` 编译实际板级探测源文件，通过供电失败、控制器失败、插槽失败、卡超时、内存不足、扇区读取失败、不支持的扇区尺寸和成功共 8 个分支，验证状态、失败通知及资源释放。设置持久化与 PSRAM 回归测试通过，ESP-IDF 6.1 构建通过。

2026-10-18 使用设备所在 Windows 电脑的 COM5 烧录应用区 `0x10000`，哈希校验通过，保留内部设置和应用数据。应用镜像 5,002,336 字节，SHA-256 `2b5dbe2f7c32d46a8c84e6f2857e604356f53afd1055f75f670095812ce508fb`。

实际 SD 卡：`TW000`，容量 `31,266,439,168` 字节，扇区 512 字节；detected=1、readable=1、error=ESP_OK、mounted=0。此结果只证明识别与原始扇区读取成功，不证明文件系统类型、剩余空间或文件读取能力。

`python tools/test-device-bottom-guard.py --port COM5` 验证从导航区短滑取消、完整上滑回家均不改变应用滚动位置，从应用内容区域开始则可正常滚动；桌面有 9 个应用图片圆角容器，截图复核通过。设备原生手势回归最终 7 项通过，堆完整性检查通过。首轮手势原生测试曾有 1 项失败、未保留当时的详细日志；加入日志捕获后重跑通过，不据此承诺时序压力下零失败。
