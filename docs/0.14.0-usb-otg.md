# 0.14.0 原生 USB OTG 服务

接口是板上原生 **USB OTG Type-C**，使用 P4 的 HS UTMI 控制器（USBD_N/P，DM49/DP50），不是 CH343/COM10，也不是 GPIO24/25 的另一个 FS 控制器。COM10 继续用于烧录、日志和 OPK1。没有启动 BSP USB Host。

## 实现与使用

电脑枚举为一个组合设备：UAC2 扬声器、UAC2 麦克风、CDC NCM 网络适配器。音频固定 PCM16、16 kHz、单声道，桌面音频的格式转换由 Windows 完成。网络目标为 Windows 11 原生 NCM 驱动；没有实现 Windows 10 的 RNDIS 回退或 Windows 原生 WLAN 扫描接口。

设置 → USB OTG：

- USB 默认开启；电脑选择 Ouse Speaker / Ouse Microphone 后请求音频流。USB 音量沿用板子音量/静音，主机侧可做软件音量处理。
- USB 网络共享默认关闭，每次启动恢复关闭。先在设备连接 Wi-Fi，再开启共享。电脑通过 DHCP 获得 `192.168.77.0/24` 地址，设备网关为 `192.168.77.1`，DNS 从 Wi-Fi 上游取得。Wi-Fi 选网仍由设备完成。开启后 Windows 可能自动选择 USB 默认网关，测试或链路切换期间可能短暂影响电脑上网；关闭共享会撤销设备端网络链路。不会通过电脑命令禁用原有网卡或修改其接口 metric。
- 关闭 USB 相当于软件断开整个组合设备。不会关闭 Wi-Fi、显示或串口安装服务。USB/共享开关本轮不写入持久设置。

这是 IPv4 NAPT 路由，不替换 STA 接收回调，不做 Wi-Fi 二层桥接，不让电脑直接控制 C6。USB 网段与上游子网重叠时拒绝共享，快照报告 `subnetConflict`；不自动更改用户路由或 Wi-Fi 地址。没有 IPv6 转发、端口映射、测速承诺或外部驱动安装。

## 生命周期与预算

音频唯一硬件所有者仍是 `ouse_board_audio_worker`。USB 音频以 `ouse.usb` 系统所有者登记 `audio/usbDuplex` 任务，使用原有 ES8311 / I2S 双工通道，没有第二个 codec 实例。电脑请求音频后接管当前音乐；USB 占用期间普通音乐、短录音和测试音请求被拒绝。闹铃优先取消 USB 音频，等待驱动实际关闭后播放，闹铃结束后 USB 在主机请求仍有效时重新申请。USB 结束不会自动续播被取消的音乐。

主机关闭两个音频流、拔线/挂起、关闭 USB、系统 drain 都使音频退出、关闭 codec 并停止 I2S，之后才能进入任务终态。共享驱动对象和 DMA 句柄沿用原有缓存复用策略，错误时释放；任务结束不代表服务栈与全部缓存已经从堆移除。后台活动页停止 USB 音频会保持停止，直到新的主机流请求；不通过 JS 后台许可维持 USB。应用关闭/更新/卸载与系统 USB 会话互不绑定。挂起撤销麦克风请求；恢复后要求主机重新选择活动流，必要时在设置关闭再开启 USB，使电脑重新枚举。

I2S DMA 使用六个 64 帧周期（约 24 ms），相对原来的 256 帧周期降低 4 倍 DMA 缓冲需求，保留 16 kHz/RX 左声道/输出复制配置。音频每次处理 64 样本（4 ms），I2S 读写等待各有 50 ms 上限。TinyUSB PCM FIFO 每方向 1,024 字节，扬声器通过显式反馈端点和 FIFO 占用修正主机发送速率，麦克风由 TinyUSB IN FIFO 流量控制调整包长；不把 RTOS 调度周期当作精确音频时钟。`underruns` 统计一次板级读取未满 64 样本的次数（包括初始填充）；`overruns` 统计麦克风 FIFO 无法接收完整批次的次数，均为启动以来累计值。

开启网络共享登记 `network/usbSharing` 任务；无 Wi-Fi 时处于等待连接的服务状态。取消、断网或 USB 停止会关闭 DHCP/netif 和 NAPT，清理失败报告 `networkStopping`，不会提前确认实际停止。数据路径每方向固定四个 Ethernet 帧槽位，每帧上限 1,514 字节（首次开启时分配在 PSRAM），无逐包堆分配；队列满时丢包并计数。已交给 lwIP 的 RX 帧由其释放，缓冲池保留至重启，避免迟到的 pbuf 回调访问已释放内存。TinyUSB NCM 每方向两个 2,048 字节 NTB，NAPT 上限 64 条，无端口映射。NTB/PCM DMA 缓冲位于内部 RAM，新增 TinyUSB/协调任务栈各 4 KiB；实际剩余堆需要真机观察，原有 HTTPS 低堆/超时问题没有在本轮宣称解决。

## 查询接口

```js
const usb = Ouse.usb.get();
// available, enabled, mounted, suspended
// speakerRequested, microphoneRequested, audioRunning
// audioTaskId, networkTaskId, session
// networkEnabled, networkUp, networkStopping, uplink, subnetConflict, ip
// sampleRateHz=16000, channels=1
// underruns, overruns, rxPackets, txPackets, droppedPackets
// errorCode, networkErrorCode
```

返回普通对象快照，不执行 I/O、开启录音或提交 USB 控制请求。`mounted` 仅表示 USB 配置完成，不代表 Windows 已打开音频流或已获取 DHCP 地址；`networkUp` 代表设备端共享路径开启，不是外网连通性证明。包计数统计接收交给 lwIP / 发送复制进 NCM 的帧，不是 Windows 实际收到的字节数；丢包计数包括关闭状态、无槽位和无连接时的丢弃。

控制 USB 属于原生设置；本轮没有给任意 BPK 全局 USB 开关或原始端点访问权。系统服务测试 BPK 通过“查询服务与时间”显示 USB 状态；后台活动和系统健康包含 USB 原生任务/服务。C API 13，JS API 1。

## 依赖和验证

新增锁定 `esp_tinyusb=2.0.1~1` 与 `tinyusb=0.21.0~2`，从 Espressif 组件注册表获取，其余已有依赖版本、分区、字库、显示及音频 RX 左声道修复保留。此版本包含 DWC2 复位前保存 GSNPSID 的官方修复，避免较早版本在新 P4 控制器复位期间读取不到版本、错误等待自清除位并占满 CPU 的问题。同时包含新版 Windows 11 NCM 对 NTB divisor 要求至少为 4 的互通修复。音频 class 配置通过组件编译选项统一注入，没有修改 managed vendor 源码。

直接相关的主机验证：任务/音频焦点检查增加 USB 排他、原生入口限制、闹铃抢占和取消确认；真实 QuickJS 服务绑定检查 USB 快照字段及复制隔离。固定 IDF 6.1 工程统一构建。构建、枚举、真实音频、DHCP/NAT 和外网访问是不同验证层级，最终设备记录另行补充；不能仅根据编译成功宣称 Windows 声卡、麦克风或网卡已经验收。
