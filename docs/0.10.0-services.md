# 0.10.0 原生网络、媒体与系统闹钟

当前源码 0.10.0、核心 C API 9、JS API 1。本轮集中实现后统一主机检查及固定 IDF 构建已通过；未烧录，也未进行本轮真机功能或音质验收。沿用固定 IDF 6.1.0、现有依赖、分区、字体及 LCD/I2S 修复；GPIO、USB 外设接口和正式音乐/闹钟业务 BPK 不在本轮。

## 授权和能力查询

清单 `capabilities` 接受布尔 `network`、`media`、`alarms`，另保留 `background`、`notifications`。未声明的能力默认禁用。`Ouse.system.capabilities()` 返回当前原生服务是否初始化成功、实际格式与上限，以及当前包获得的能力。硬件/网络能否实际工作仍以请求结果为准。

```js
const caps = Ouse.system.capabilities();
// caps.network / caps.media / caps.alarms / caps.granted
```

原生媒体会话和持久闹钟均不依赖 `background.begin()`。声明这些能力不会授予后台 JS；持续通知也不会保持实例或授权 JS。旧实例关闭后不接收旧 Promise/任务回调。重新打开的实例通过服务快照查询属于同一 app ID 的会话/闹钟。

## 网络

```js
const request = Ouse.net.request({
  url: 'https://your-server.example/api',
  method: 'GET', // GET / HEAD / POST / PUT / PATCH / DELETE
  headers: {Accept: 'application/json'},
  timeoutMs: 10000,
  responseType: 'text' // 或 bytes，返回 ArrayBuffer
});
const taskId = request.taskId;
request.then(response => {
  // status, ok (2xx), headers: [[name,value],...], bodyBytes, body
}, error => { /* error.name / message / code */ });
Ouse.tasks.cancel(taskId); // 只请求取消，以终态确认停止
```

只接受 HTTP/HTTPS、ASCII 编码 URL，国际域名/路径需由调用方编码。URL 最多 512 字节；字符串请求体最多 8192 UTF-8 字节，GET/HEAD 不接受请求体；最多 12 项请求头，名称/值分别最多 63/255 字节，禁止 CR/LF、重复名称以及 Host/Content-Length/Transfer-Encoding/Connection/Accept-Encoding 等由原生层管理的字段。响应体最多 32768 字节，响应头同样最多 12 项、总字段和值最多 4096 字节；超限明确失败，不静默截断。text 解码按引擎 UTF-8 规则；二进制用 bytes。

不跟随重定向、不自动重试、不解压、不保留 cookie，也不提供 TLS 校验绕过、代理、任意文件写入或 JS 流式字节回调。3xx/4xx/5xx 是有效 HTTP 响应，Promise 正常完成且 ok=false；传输/解析/容量错误才拒绝。HTTPS 使用固定 IDF 自带 CA bundle 并验证主机名，系统时间无效时可能证书校验失败。

每实例最多 2 个未消费请求，全局 JS 请求/结果最多 16 个，原生请求队列 8 个、一个网络工作任务，栈 12 KiB。响应缓冲固定上限且有界保留，挂起不执行 Promise。超时 1000..30000 ms，从接受请求开始包含排队时间，使用单调经过时间；连续响应头不能重置这个整次请求的截止时间。DNS 是固定 IDF 同步解析，可能越过取消/超时请求，服务在其返回后立即清理并报告；不宣称能即时抢占 DNS。网络关闭实例策略是请求停止，实际连接/TLS 清理结束后才终态。

底层 `ouse_http_transfer` 只供原生工作任务使用。它有独立的头部/连接期限、网络读取空闲期限和调用方提供的总期限，并允许原生有界 sink 背压。媒体消费不会绕 JS 搬运流。

## 媒体和音频仲裁

```js
const id = Ouse.media.play({asset: 'tone'}); // binary 包资源，原生复制
// 或 Ouse.media.play({url: 'https://your-server.example/song.wav'});
Ouse.media.pause(); Ouse.media.resume(); Ouse.media.stop();
const state = Ouse.media.get();
// null 或 taskId/state/active/paused/interrupted/buffering/
// positionMs/durationMs/bufferedBytes/error/errorCode/revision
```

媒体需 media 能力，URL 音源还需 network。一个全局会话，忙时明确拒绝；控制和快照只面向所属 app ID。play 返回公共任务 ID 或 false；pause/resume/stop 返回布尔接受结果。停止只是取消请求，任务终态要等待生产任务、网络连接及 codec 均释放。源数据不引用 BPK 实例；Home/关闭实例后继续，重新打开可查询/控制。更新保留同 app ID 的会话；撤销 media 能力时请求停止，卸载在原生安装任务上等待清理。

首个格式是 RIFF/WAVE、PCM16、单/双声道、8..48 kHz。原生读取器按输入采样率转为板上既有 **16 kHz 单声道**，采用整数抽样/重复采样，不能称高保真重采样。包内音源最多 64 KiB；HTTP 音源最大 128 MiB，总会话上限四小时，网络连接/头部和空闲期限 15 秒。尚不支持 MP3/AAC/FLAC、文件浏览、SD 卡媒体库、seek、范围续传、自动重连或播放队列；不得向开发者宣称这些格式已可用。正式音乐应用前需评估解码器及音质，保持现有依赖版本不变。

独立原生生产任务读取/解析，固定 **8192 字节 PCM 缓冲**，现有唯一音频任务保持 ES8311/I2S 所有权；没有 JS 音频搬运，也不把网络等待放进 codec 消费循环。闹铃优先，媒体保留会话/缓冲和用户暂停状态，释放 codec 后交给闹铃，再尝试恢复。网络服务器可能在暂停/抢占期间关闭连接，恢复失败将按真实错误结束，不承诺无缝续播。已有短测试音/录放仍保留；普通短音频替代正在播放的媒体会请求结束媒体，排队媒体不会被无记录覆盖。

## 时间与系统闹钟

```js
const clock = Ouse.clock.get();
// utcMs / valid / syncedThisBoot / lastSyncUptimeMs / source
const id = Ouse.alarms.set({
  id: 'morning', title: '起床', atMs: clock.utcMs + 60000, payload: 'morning'
});
Ouse.alarms.set({id: 'weekly', title: '工作日', weekdays: 62,
  minuteOfDay: 7 * 60 + 30, utcOffsetMinutes: 480});
Ouse.alarms.list();
Ouse.alarms.dismiss('morning');
Ouse.alarms.snooze('morning', 5); // 当前正在响铃的闹钟，1..60 分钟
Ouse.alarms.remove('morning');
```

clock.valid 仅指系统壁钟落在 2024..2100 的合理范围，**不代表准确度或本次联网成功**；syncedThisBoot 只由 SNTP 成功回调设置。没有 JS 任意改系统时间接口。闹钟以 UTC 秒调度，atMs 向下取整到秒；weekdays 为周日 bit0..周六 bit6，0 表示一次闹钟，否则 minuteOfDay 为 0..1439，每条闹钟保存 -720..840 分钟的固定 UTC 偏移。没有自动 DST 或系统时区编辑功能。

需 alarms 能力，全局 24 条，每 app ID 最多 4 条，命令队列 8，原生闹钟任务栈 4 KiB。ID 是 1..31 个 ASCII 字母/数字/下划线/连字符，title/payload 分别最多 95/127 个 UTF-8 字节。set 同 ID 替换；修改/删除要等任务成功才表示落盘，原生快照只显示已提交状态。关闭和更新包保留，卸载先撤销触发资格，再经 FIFO 清理；包撤销 alarms 能力后不再触发。暂时无法恢复的包保留原记录，不因 OOM 或坏包而删除用户闹钟，恢复/重新授权前不触发。

记录写入 `/bpkfs/ouse-system/alarms.bin`，明确小端磁盘格式、版本、CRC，临时文件 flush/fsync 后原子替换。损坏文件不自动擦除或格式化；服务不可用及错误可诊断。系统文件占文件系统物理用量，不计为某个应用的私有 JSON 字节。

无有效壁钟时等待；每 250 ms 原生检查（另受文件 I/O 和调度影响，非硬实时）。迟到不超过 120 秒可触发，超出记 missed，重复闹钟直接推进下一次，不补播全部历史；保存 last occurrence 防止向后校时重复触发。先提交已消费状态，再发系统持续通知和有界闹铃，选择跨重启的至多一次效果；若在提交与响铃之间断电可能漏响，不能承诺恰好一次。闹铃最长 60 秒，多个闹钟共享音频优先级，停止/稍后不依赖 BPK JS。当前使用全局音量/静音；不支持独立闹铃音量或自定义铃声。

这是运行中系统闹钟，**不支持关机唤醒或深睡唤醒**。当前电源服务的自动熄屏可继续运行原生任务，不能把熄屏与关机混称。

## 开发与验证

`apps/service-test` 是独立 JSON＋JS 分类测试 BPK，手动填写 URL 才发请求，提供包内 WAV、媒体控制、一次闹钟和清理按钮，不申请后台 JS。已打包，未安装或真机验证。

编辑器网络预览只返回明确 simulated 的结果，不会实际访问输入 URL；时间来自电脑，闹钟只模拟一次记录且不跨重启保存，媒体能力明确 unavailable，不伪造音频成功。预览切页保留实例、任务订阅和后台申请，只有重启预览才清理。

任务登记新增 network/alarm 摘要。大结果仍只走 Promise/原生缓冲；新增 resultPending 钉住终态记录，直到结果消费/丢弃或实例关闭，完成事件被消费不再提前释放 Promise 所需的记录。音频收尾错误归 failed，不能被取消请求掩盖。

本地必要验证已通过：生产 HTTP 分片/分块/尾部/HEAD/EOF/畸形帧/容量/整体期限及清理，WAV 分片与采样转换，原生媒体生产/消费收尾、暂停满缓冲期限和取消错误分类，实际音频任务 codec 抢占/恢复，闹钟真实主机文件落盘/恢复/CRC/提交失败/校时/权限/取消/FIFO 清理，真实 QuickJS 服务绑定、挂起/恢复、重入 getter 和旧实例隔离。旧任务/预算/后台、Wi-Fi 收尾、安装校验交接、预览、TypeScript 与 BPK 打包亦通过。主机 FreeRTOS/TLS/codec 使用确定性替身，不能证明设备调度时序、真实服务器/TLS 互通、断电一致性、音质或长期稳定性。

统一检查初轮 14 组中 12 组直接通过；两处新测试夹具问题分别是 Windows rename 声明受宏污染，以及在 Promise 微任务执行前检查回调。修正夹具后只复核受影响服务组，未为消除这些失败修改生产逻辑；另补暂停期限和 codec 清理错误的直接边界检查。没有重跑大批历史单元测试或长期压力测试。构建一次通过，保留上游已有 Kconfig 通知。
