# Ouse Core 0.3.0

OusePocket 的轻量核心，仓库根目录就是 ESP-IDF 工程入口。旧 Brookesia 源码、微雪完整示例和历史文档保存在 `legacy/`，新固件不依赖该目录。

当前支持微雪 ESP32-P4 WIFI6 Touch LCD 3.5，芯片 revision >= 3.1；实测板为 v3.2、16MB Flash、32MB PSRAM。

## 当前功能

- 标准桌面只有顶部状态栏、应用图标/名称和底部手势条；去掉品牌大标题、版本号、启动提示和说明文字。按归档的 112px 网格/18px 间距自动计算列数和横向分页，显示全部已注册应用；最多一个前台应用，其余实例可以保留在最近应用中。
- 从屏幕左右边缘向内滑返回；系统信息页先返回设置，再侧滑返回桌面。
- 从顶部向下滑打开快捷面板，调整、保存亮度；向上滑、侧滑或点收起返回。
- 从底部向上滑进入最近应用；卡片有真实界面预览，可左右滚动、点击恢复、上滑关闭，也可点卡片右上角关闭。
- 最近应用为空时显示空态；底部手势条也可点按进入最近应用。
- 注册信息复制到固定容量表中（最多 8 个，包含内置设置），启动时校验 id、重复注册和容量，启动后冻结注册表。
- 应用按需创建界面；返回桌面或切换时 pause 并保留状态，恢复时 resume。关闭时先回调清理资源，再由管理器删除界面树和预览。重复打开当前应用不创建新实例；未知 id 保留当前应用。
- 打开失败时也调用清理回调、删除部分界面并回到桌面；阻止生命周期回调内重入打开/关闭。
- 计数器支持加一、清零和本次运行时间。返回桌面保留计数并暂停刷新；点卡片恢复原数值。上滑关闭后销毁定时器和状态，再打开从零开始。
- 设置也按需创建；返回桌面暂停其刷新定时器，关闭卡片才删除界面和定时器。
- 使用归档浅色/深色语义配色，设置的“外观”和下拉面板均可切换；共享 LVGL 样式同步更新缓存应用，不丢失计数。默认浅色，主题与亮度一起异步保存到 NVS。
- 状态栏显示系统时钟和未知电量占位；时钟未校时显示 --:--，未提供电量接口时不伪造百分比。当前无线服务关闭，不显示已连接状态。
- 保留 0.2 的亮度保存、系统信息与返回导航。
- 设置使用独立 NVS 命名空间 `ouse_core`。启动恢复亮度，默认 45%；拖动立即调光，松手或点击保存后提交后台任务。
- 保存任务只处理 NVS，不操作 LVGL。滑动期间不写 Flash；排队请求合并为最新值，同值已保存时不重复写入。
- 界面区分正在保存、已保存、失败重试。初始化失败保留 NVS，不自动擦除，仍尝试进入桌面。
- 系统信息页显示 CPU 配置频率、内部堆与 PSRAM 的空闲/总量、Flash 物理容量、运行时间和 SDK 版本。只在页面可见时约每秒刷新。
- 显式设置深色背景不透明度，不依赖默认主题。

CPU 频率不是 CPU 占用率；内存总量是对应能力可分配的堆总量，不是芯片 SRAM 标称容量。Flash 显示物理容量，不表示文件系统剩余空间。暂未接入 Wi-Fi、蓝牙、音频、JS、BPK 或 USB 安装服务。

## 固定版本

核心 0.3.0，公共核心 API 3。ESP-IDF 6.1.0（开发机提交 `fff9895c82d744c7237be8847347bdd1b07c6643`）、LVGL 9.5.0、微雪 BSP 2.0.2、ESP LVGL Adapter 0.6.4。组件清单与 `dependencies.lock` 固定依赖；不保证任意 ESP-IDF 6.x 可直接替换。

CPU 400MHz、PSRAM 200MHz、XiP 开启，LVGL 使用单绘制单元，Adapter UI 任务采用 8KiB 内部栈。

## 构建与手动烧录

在 ESP-IDF 6.1 终端，从仓库根目录执行：

```powershell
idf.py build
python -X utf8 tools/package-firmware.py
```

在图形 FLASH DOWNLOAD TOOL 中，只选择 `tmp/ouse-core-0.3.0-full.bin`，地址 **0x0**，选择 DIO、80MHz，保持 DoNotChgBin 勾选，点击 START。其他旧文件全部取消勾选，不点 ERASE。

合并镜像含 bootloader、分区表和主程序，空洞为 0xFF，因此会重置原 NVS 设置。它不写入 LittleFS。后续同分区布局升级如需保留设置，只烧录 `tmp/ouse_core_desktop.bin` 到 **0x10000**。

也可按 `tmp/README.md` 分别烧录三个镜像。`tmp/symbols/0.3.0/` 保存匹配 ELF/MAP，供异常解析，不参与烧录。

## 线程和接口约定

- `ouse_system_init()` 由启动入口调用一次，之后系统信息查询和保存状态读取可从任务调用；这些 API 不创建界面。
- `ouse_system_request_brightness()` 返回成功仅表示请求已接收，完成结果应读取 `ouse_system_get_settings_state()`。后台任务处理可能合并的最新请求，状态使用序号防止旧完成覆盖新请求。
- `ouse_core_start()` 由启动入口调用一次，不允许并发启动，也不要持有 UI 锁调用。
- LVGL 事件和定时器在 Adapter UI 锁内运行，可直接操作界面。其他任务通过 `ouse_core_post_ui(callback, context)` 提交回调，最多 8 个待执行调用；失败返回超时或内存不足，由调用者处理。
- 回调在 LVGL 任务执行，必须短小，不能等待网络、写 Flash、阻塞或再次调用 `post_ui`。context 必须在执行前保持有效，不能传入提前失效的局部变量地址。
- 系统信息页面的刷新定时器只读取内存统计与状态，不轮询 USB，不创建安装服务。

## 应用开发接口（0.3 原生验证阶段）

`ouse_app_definition_t` 包含唯一 id、名称、图标、open、close 和长期有效的 context。
在 `main.c` 中通过 `ouse_core_config_t.apps/app_count` 提供额外应用，系统会自动注册内置设置并生成桌面入口。
现成示例见 `main/counter_app.c`，与核心界面代码分开实现。

`open(root, context)` 在 UI 任务中构建控件、创建定时器；root 尺寸已完成布局，所有子控件由管理器统一销毁。
`close(context)` 必须容忍只完成部分初始化的情况，先取消自己的定时器/异步资源、清除指针，不要删除 root。
`pause/resume` 必须成对提供。拥有定时器等工作的应用必须在 pause 中暂停，在 resume 中恢复；没有后台任务的应用可以省略这对回调。
本版的“最近应用”保留界面和状态，不提供任意应用后台执行能力。`ouse_app_background()` 回桌面并保留，`ouse_app_close()` 关闭前台实例，`ouse_app_close_id()` 关闭指定实例。
`ouse_app_get_recent()` 按最近激活顺序返回保留的实例；`ouse_app_get_preview()` 返回借用的预览图，调用方不得释放或在实例改变后继续引用。桌面卡片持有独立拷贝，重建或关闭面板时释放。
后台线程、安装/卸载、动态包和 JSON＋JS 运行时尚未提供。

`ouse_app_open(id)`、`ouse_app_close()`、`ouse_app_get_info()`、`ouse_app_get_stats()` 都要求在 UI 任务或 UI 锁内调用；其他任务用 `ouse_core_post_ui()` 提交。
统计提供注册数、保留实例数、成功创建/关闭次数、失败次数、预览内存和前台 id。生命周期回调内禁止重入打开/关闭；不允许在回调中阻塞。
应用关闭前须清理自身异步资源，本版尚未为任意应用工作线程提供自动取消机制。

## 验收

0.1.0 已由用户烧录确认绘制和触摸正常。用户日志显示 PSRAM 自检通过、约 1.81 秒桌面 READY，无启动异常；不能据此断言旧 Core1 故障根因已修复。

0.2.0 用户日志进一步确认启动恢复了 35% 亮度，桌面 READY，无启动异常。照片显示深色背景和保存状态正常。

0.3.0 最终固件实机启动日志已确认：ELF 指纹 `4cd5a834a…` 匹配，恢复 65% 亮度，约 1.84 秒桌面 READY，无启动崩溃或初始化失败。此日志不覆盖长时间运行及全部交互。

0.3.0 后续实机交互验收：

1. 桌面只有状态栏和设置、计数器两个图标，没有品牌/版本/说明。计数器加一后从左右侧边分别向内滑回桌面，再打开仍保留数值。
2. 顶部下滑打开快捷面板，调亮度并保存；上滑或侧滑收起，不影响应用状态。
3. 底部上滑进入最近应用，卡片应显示退出时画面；左右滚动切换，点击恢复原状态。
4. 卡片上滑关闭后应消失，重新打开计数器从 0 开始；两个卡片都关闭后显示空态。
5. 设置、系统信息、计数器和面板之间反复操作几十次，检查返回、滑块、手势不互相误触。
6. 在设置或下拉面板切换浅/深色，桌面、设置、快捷面板及最近卡片都应同步变色；保留实例的计数不变。等设置保存后断电重启确认主题和亮度恢复。
7. 串口有 `OuseApps: Registered/Opened/Background/Resumed/Closed` 日志。后台保留实例暂停 UI 刷新，关闭才释放资源。

保留此前基础系统验收：

1. 深色背景、文字对比、设置和返回正常。
2. 亮度改为例如 70%，松手后等提示“已保存，重启保留”；断电重启后仍为 70%。不要通过重刷合并 bin 验证保存，因为它会重置 NVS。
3. 系统信息数值合理，停留时运行时间递增，返回后可重复进入。
4. 多次软重启、断电启动和桌面/设置/系统信息切换，保留首次异常完整日志及匹配 ELF。

## 手势与内存说明

侧边起点宽度 24px，横向向内至少 48px；顶部起点在 36px 内，下滑至少 48px；底部起点在 28px 内，上滑至少 48px。最近卡片上滑至少 56px 才关闭，方向必须以垂直位移为主。

手势使用 LVGL 输入设备的按下/释放坐标识别，触摸仍由 BSP IRQ 输入链路提供；不依赖 `LV_USE_GESTURE_RECOGNITION`，因此该功能未启用的提示不表示上述手势不可用。没有新增 USB 轮询服务。

应用界面保留在 RAM 中；背景时保存 RGB565 预览，320×432 每份约 270KiB。最近面板为避免跨实例的悬空图片引用，再复制可见卡片的数据，面板收起时释放。最多注册 8 个应用，不对任意应用的内存占用作无限保证；预览分配失败时仍提供可点击恢复的卡片。

## 原生移植说明

直接复制了归档的手势辅助头文件；时钟格式和网格排列使用归档 C++ 算法。原 ShellApp 的控件创建依赖 GUI 模板绑定层，因此其视图按原模板/portrait 常量移植为 LVGL C 控件；明暗配色成为 C 共享样式。UI 不运行 JS、不加载 JSON。来源记录在 `components/ouse_core/BROOKESIA-NOTICE.md`。

主题共享样式作用于缓存界面；最近应用预览在读取时发现主题已变会重新生成。亮度与主题通过同一个最新设置快照入队，避免快速连续更改时互相覆盖。
