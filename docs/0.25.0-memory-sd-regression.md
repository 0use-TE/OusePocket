# Core 0.25.0：内存压力、SD 恢复与主机回归

## 内存策略

以实时内部 RAM 空闲量、最大连续块和 PSRAM 空闲量分级，任一指标触发即生效：

| 等级 | 内部空闲 | 最大内部连续块 | PSRAM 空闲 |
| --- | --- | --- | --- |
| 警告 | <64 KiB | <16 KiB | <1 MiB |
| 临界 | <32 KiB | <8 KiB | <512 KiB |

警告时不再生成最近应用预览；打开新实例前先清理可重建预览和已配置的图片缓存，再检查压力。仍为临界则拒绝并显示内存不足提示，保留当前实例和未保存内容。已存在实例可以恢复，设置仍可打开以关闭后台应用。不会为了腾内存强杀音乐、录音或笔记。

脚本桥在临界压力下拒绝新 HTTP、RAM 采音、SD 录音及摄像头启动；停止、取消与清理不受该准入限制。服务仍检查各次分配结果。此策略减少进入危险状态的概率，不是为任意第三方应用提供硬实时内存预留，也不代表内部 RAM 空闲量会增加。

## SD 生命周期

- 文件服务、目录缓存和工作线程只创建一次，重挂载重复使用。
- 设置设备信息页提供“重新检测 SD 卡”；脚本也可调用 `Ouse.files.recover()` 并轮询 `recovering/ready/error`。
- 重挂载前阻止新租约；有播放文件、录音、下载或其他文件操作占用时拒绝，而非强制关闭文件。
- 安全卸载后保持卸载，必须手动重新检测。恢复时仅重建 SD 卡自己的槽位并重新识别，不销毁或重置共享控制器及 Wi-Fi 槽位。槽位重建和卡初始化通过共享递归总线锁串行执行，避免遗留的总线位宽与时钟状态影响重新识别。
- 状态检查发现异常后标记不可用；没有占用时以工作线程约两秒间隔最多自动尝试三次，失败后可手动重试。首次启动没有识别成功的卡也可手动重新检测。
- 不重置或销毁 SD 与 Hosted Wi-Fi 共用的控制器，不删除其供电句柄，不自动格式化。格式不支持时保留数据并返回错误。
- 这不是可在写入中任意拔卡的保证；应先停止使用并安全卸载。无法修复已损坏的 FAT，也不能保证被强拔时尚未落盘的数据完整。

## 统一离线回归

在仓库根目录运行：

```powershell
python tools/test-regression.py
python tools/test-regression.py --only ui files sd-board protocol
$env:OUSE_CORE_ASAN='1'; python tools/test-ouse-core.py
```

需要现有 MSVC/Windows SDK、Python、Node.js，以及已安装的工程依赖；不会连接串口或烧录。`--only` 自动加入所选测试的夹具准备依赖，避免依赖残留的 `.tools` 缓存。结果写入 `.tools/regression/report.json`，逐项日志在同目录。UI 默认 24 轮应用生命周期，`python tools/test-ouse-core.py --stress` 使用 200 轮。

17 项包括真实 LVGL/输入法及生命周期、内核、系统、协议边界、服务、文件恢复、板级源码约束、音频、混音、采音格式、SD 录音、权限、网络通道、倒计时、网络应用、录音应用和 BPK 包校验。修复隐藏控件误选、过期页面文案、异步 Wi-Fi 夹具残留、键盘事件不匹配及旧手势快照断言。

UI 的外设使用契约替身，真正的服务另有独立测试；SD 文件测试使用临时目录和错误注入。板级测试编译真实的 `board_sd.c`，以 SDK 替身验证重复槽位重建、冷启动及卡识别/删除槽位/创建槽位/挂载失败重试，同时检查禁止销毁共享控制器；这不是完整 ESP-IDF 控制器仿真，不能代替实机验证。槽位句柄兼容入口依赖当前 ESP-IDF 6.1，升级 SDK 时需重新核对驱动与实机共存行为。

低内存测试注入临界状态并验证拒绝、新实例保护、设置例外、恢复已有实例和预览释放。SD 测试覆盖重复卸载/重挂载、占用拒绝、排队栅栏、挂载/卸载失败、三次有限自动恢复以及工作线程不重复创建。

## 桌面单页滑动修正

桌面使用 `LV_OBJ_FLAG_SCROLL_ONE` 配合同宽页面居中吸附，避免一次快速滑动跨过多页，并关闭桌面的弹性越界，防止首尾拖动回弹后反向翻页。当前 LVGL 的起点吸附边界可能把已对齐的当前点当作零距离边界并放开限制，因此不能只增加标志而保留起点吸附。主机测试覆盖七页连续双向滑动、快速滑动以及首尾边界；更新应用分区后，真机 28 个应用、三页双向滑动和边界检查通过，自检正常，停留第一页并释放串口。
