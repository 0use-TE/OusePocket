# 0.39.2 蓝牙重连修复

- 电脑/手机作为 central 连入时也主动请求链路加密，恢复已有 bond；显式 plain 应用连接保持原策略。
- 用户开启配对窗口后允许删除对端旧密钥并重试配对，窗口外保留拒绝策略；仍需确认数字。
- 断线回调不立即申请广播连接槽，worker 在 host 完成清理后恢复广播，最多约 2 秒。
- 记录加密状态、断开原因和未加密超时，便于区分远端断开与本机策略。

验证：生产 GAP 回调事件测试、BLE 命令策略测试、应用连接所有权测试。
实际电脑端配对、加密与持续连接以真机日志为准；构建通过并不等于 Windows 配对已验证。

真机结果（2026-10-20，COM10）：已烧录 0.39.2，校验哈希通过；保留 13 个应用。旧配对期间抓到远端终止 0x213，未能完成加密。用户删除电脑及设备旧配对并重新确认数字后，日志显示 Encryption status=0、connected=1、encrypted=1、bonded=1、error=0；用户确认连接正常。
证据：.tools/ble-fix-repairing.log；.tools/ble-fix-stable.log。此前 rc=6 也存在广播与新连接并发的竞争，worker 延后重试保证广播恢复；不宣称完全消除所有并发 rc=6。
