# Core 0.27.0：蓝牙设置与运行错误详情

## 录音机授权故障

真机先把录音机麦克风权限切回“询问”，再点击录音和允许，原包稳定出现 `TypeError: not a function`。授权轮询回调调用了未提供的 `Ouse.timers.clearInterval`；已有权限时不会进入这个分支，因此旧测试漏过了问题。相册共享删除授权存在同样调用。

两个应用已改用标准的 `Ouse.timers.clear(id)`，同时固件增加 `clearInterval` 和 `clearTimeout` 兼容别名，旧包也可以受益。没有清空应用数据或重置全部权限。新增测试覆盖询问后允许、拒绝、超时、暂停及定时器释放。

## 错误详情

故障页直接展示应用 ID、实际异常和 QuickJS 调用栈，日志区域可以纵向滚动，底部返回桌面。单次详情限制为 1,024 字节，避免异常信息本身耗尽内存；不执行出错应用的 UI 来绘制错误页。无法取得调用栈的异常仍显示消息。

原生 API 30 新增 `ouse_runtime_get_error()`，保存最近一次首次故障快照，位于 PSRAM，重启清除。开启设备调试时，`DBG_ERROR` 返回资源长度和 CRC，随后用 `DBG_READ` 分块读取、`DBG_FREE` 释放；这不是全部系统日志，也不向其他 JS 应用暴露。

## 系统 BLE

设置新增蓝牙页：开关、10 秒有界搜索、可被发现、连接、断开、忘记绑定。设备名称为 OusePocket。开关偏好和绑定保存在 NVS。启动默认关闭；开启时按需启动 NimBLE，关闭停止扫描、广播和连接，但已经启动的主机栈内存保留到重启。

使用现有 ESP-Hosted HCI over SDIO，不更新 C6，也不调用依赖新版本 C6 的蓝牙控制器初始化 RPC。Wi-Fi 与 BLE 共用串行化的底层链路准备入口，因此不要求先开启 Wi-Fi。内部内存不足时拒绝首次启动。

安全策略为 Secure Connections、MITM、数字比较和绑定。新配对窗口 120 秒、确认窗口 30 秒，拒绝过期或不匹配的确认 ID；不通过自动删除旧绑定来接受重复配对。最多一个连接、四个绑定、十六个扫描结果。测试 GATT 服务只允许经过认证的加密读写，最多 32 字节的回显，不提供文件访问。

当前范围不包括经典蓝牙、蓝牙音乐、HID 或第三方 JS 蓝牙 API。系统管理、电脑配对和加密 GATT 已通过本次硬件验收，不等于所有 BLE 外设及 HID 已经验证。
