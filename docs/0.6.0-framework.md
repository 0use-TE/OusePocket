# 0.6.0 应用框架第二阶段

第二阶段补齐应用组合控件、状态样式和系统通知。核心版本为 0.6.0，公共 C API 为 7，JS API 为 1；只有一种 BPK 格式，不增加旧格式兼容路径。固定依赖版本未变。

| 范围 | 实现 |
| --- | --- |
| 组合控件 | 新增 card、list、listItem、toolbar、divider、dialog、bottomSheet；连同前一阶段共 19 种控件 |
| 样式 | setStyle 增量合并；语义颜色引用随主题更新；pressed、checked、disabled 状态覆盖 |

| 弹层 | 应用独立遮罩，Back/背景点击关闭，支持 dismiss 回调；同一应用一次显示一个模态，切后台自动收起 |

## 开关和复选框方块问题

本轮用户真机照片指出 BPK 的开关和复选框显示为实心蓝色方块。原因是固定配置关闭了 LVGL 默认主题，运行时只为控件设置颜色，缺少圆角、滑块间距、对勾图像等完整皮肤；设置里的原生开关早已单独设置了这些属性。状态和事件正常不代表外观正确，早期功能检查漏掉了这一点。

修复将原生开关皮肤抽成共享函数，BPK 同样具有圆轨道、白色滑块和切换动画。复选框显式设置对勾，并为符号部件指定含 Font Awesome 符号的字体；普通文字/CJK 字体不能替代符号字体。滑条、进度条、下拉列表、圆弧和 spinner 也补齐无默认主题时需要的样式。

增量样式保留显式圆角和状态颜色，开关/复选框将状态背景映射到实际绘制的 indicator；accentColor、thumbColor 支持颜色引用、状态和 null 恢复。字体变更同步调整符号和含文字控件的最小高度。专用真机检查器保存浅深色、选中/未选中和下拉展开截图，外观需另行目视核实，不用事件通过代替视觉结论。

## 使用与限制

应用在清单声明 `"capabilities":{"notifications":true}`，使用 `Ouse.notifications.publish/update/cancel/list/onOpen`。后台发送还需单独声明 background 并主动 begin；持续通知本身不会启动后台执行。控件、样式和通知示例见 [BPK 契约](bpk.md)。

每应用最多 6 条通知、全系统 24 条；通知 ID/title/body/payload 分别最多 47/127/383/255 个 UTF-8 字节。达到上限后新建失败，已有 ID 仍可更新。点击队列全局 8 个、每应用 4 个，未投递事件最多保留 5 分钟。

通知保存在 RAM，重启后清空。普通通知支持单条清除和全部清除；持续通知由应用取消，或随应用更新/卸载清理。通知正文不会随系统语言自动重译，由应用更新自己的文案。

页面节点上限升为 96，深度仍为 8。共享脚本任务栈 64 KiB，每应用 JS 堆 512 KiB、JS 栈上限 40 KiB，前台/后台每轮预算 12/4 ms；每应用 8 个计时器。字体、dp/sp、输入法和受控后台机制沿用第一阶段。

本阶段不包含中文拼音候选、原生闹钟/倒计时/媒体会话、多资源目录或通知跨重启持久化。
