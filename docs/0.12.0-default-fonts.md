# 0.12.0 默认字号与字体池

按用户最新要求，系统只提供默认 100% 字号倍率。原生设置移除字号选择，“语言与文字”改为“语言”；保留中英文切换、主题、亮度和现有排版。标题、正文、时间数字仍使用各自的角色字号，固定倍率不意味着所有文字同大。

## 字体与接口

保留像素字体池：8、10、12、14、16、18、20、22、24、28、32、40。移除 4、6、21、48、56、64、72、84 八档生成文件。当前板级逻辑密度仍为 160 DPI。原生取字体仍按逻辑尺寸和板级密度选择最近档位，不提供额外用户缩放。

保留的主字体、共享 CJK 14/16/20px 的字形、4/2bpp 灰度、字符映射、行高、基线和 fallback 链均不改变。不生成新子集，不从正在开发的其他 BPK 中重新收集用字，不删减常用中文覆盖。移除文件只针对不再使用的尺寸。

先前提出的大字号无损压缩尝试已撤回：生成文件恢复原始未压缩数据，删除该尝试的新增编码工具和生成器修改，不启用 LVGL 字体压缩。没有增加运行时解码、临时行缓冲或新字体依赖。

`Ouse.display.setFontPercent` 移除，预览同步移除；只读显示信息 fontPercent/fontScale 固定为 100/1。C 入口中的 font_percent 参数只允许 100，初始化仍允许 0 作为默认值。旧 NVS font 键完全忽略，不读取、不写入，也不为清除它而擦除其他设置。

JSON 节点的 fontSize 保留整数 8..84 请求范围，统一就近选择实际 8..40 字体池；大于 40 的请求使用 40px，不加入大字号字库。预览同样按字体池就近选择。0.12.0 一度把请求范围缩到 40，真机发现原有计数器包因此无法恢复注册，0.12.1 已修正；包文件未删除。默认值与最近尺寸选择机制保持。需要更大的时钟数字时，应后续按具体产品需求加入独立数字字库，而不是恢复所有中文的大字号副本。分类 api-test 移除字号切换按钮，其他接口保持。

## 分区决策

先依据裁减后的实际链接体积决定是否扩区。现有 8 MiB 应用区与 LittleFS 起始地址保持，避免现有设备上的 BPK 和数据需要迁移。若本轮构建已释放数 MiB，则当前无需扩大应用区；以后加入解码器或大驱动时再按实际增量复核。

SD 卡适合媒体资源，不替代内部关键设置和无卡运行能力。最初优化阶段未连接设备；后经用户授权完成真机烧录及检查，见 [0.12.1 真机记录](0.12.1-device-validation.md)。未提供 OTA 或分区迁移。

## 验证

集中检查真实 UI 的固定倍率、角色字号与语言切换；真实设置后端验证旧 115% 偏好不再生效，非 100% 请求拒绝，原设置落盘仍正常。保留字体与此前源文件逐一比较，确认像素和排版数据未改变；核对最终 ELF 字体对象和固件占用。先完成相关检查及统一构建；后经用户授权进行有限真机验证，不运行旧字号倍率用例或长期压力测试。


## 本轮结果（2026-10-17）

相关检查及统一构建通过。主字体对象从 3,767,989 字节降到 837,704 字节；三套共享 CJK 仍为 1,265,158 字节。固件从 7,847,680 字节降到 **4,916,640 字节**，节省 **2,931,040 字节**；8 MiB 应用区剩 **3,471,968 字节，约 3.31 MiB**。因此本轮不修改分区，不需要迁移设备数据。字形与灰度数据保持，未引入运行时压缩开销。0.12.1 修正字号请求校验后体积相同，已烧录并完成相关真机检查和截图目视验收；HTTPS 超时未通过。最终身份和证据见 STATUS 顶部及真机记录。
