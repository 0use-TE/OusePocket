# 0.46.1：相机默认铺满取景

2026-10-26，Core 0.46.1 / Native API 48，相机 BPK 1.3.0（versionCode 5）。

相机默认请求全屏，隐藏顶部状态栏；手势模式使用完整页面，三键模式保留底部 40 dp 导航栏。快门在竖屏底部、横屏右侧，和相册入口一起叠在取景画面上。

实时预览保持固件 320 × 240、4:3 描述符的比例，按页面尺寸等比放大并居中，溢出部分由不滚动的 viewfinder 容器裁切。尺寸使用整数 4 × 3 单位并留少量缩放余量，避免固定点缩放舍入露出细边。横竖屏共用同一规则，屏幕尺寸变化和应用恢复时重新布局。

左上角“完整画面”按钮可切换到完整预览，此时允许留边；切换后按钮显示“铺满取景”，点击恢复铺满。模式在本次应用生命周期内保留，重新启动相机默认铺满。照片拍摄和保存不受预览裁切影响，仍保存完整传感器图像。

## 实时缩放负担

初次设备试跑中，全屏双线性采样使绘制阶段约 97 ms，CPU 0 触发非致命 task watchdog 告警。没有关闭看门狗或延长超时。0.46.1 仅为 `@camera` 关闭 LVGL 图像抗锯齿，使用最近邻缩放；照片查看及其他图像仍保留过滤。实时预览因此可能显得更有像素感，保存照片质量不受影响。修正后的实际预览绘制样本约 45～51 ms。

原生回归从生产 `ouse_runtime.c` 提取实际图像初始化段，用真实 LVGL 渲染 RGB565 测试图：在 320×440、480×280、320×480、480×320 下检查两种模式的像素、父容器裁切、相邻区域不被覆盖，以及仅实时相机关闭过滤。

设备测试逐项检查手势/三键 × 横屏/竖屏，连续预览、两种模式切换、几何和截图、三键 Home 返回及恢复；检查堆完整性、错误计数前后不增加、UART 无 task watchdog。首轮测试脚本的横屏设置项查找超时已修正为先切竖屏；该夹具失败不计为最终通过。
