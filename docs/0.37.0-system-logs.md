# 0.37.0 系统日志

设备内置原生“系统日志”应用，支持较早/较新分页、刷新、二次确认清理，以及导出全部保留日志到 SD 卡 `Ouse/Downloads/system-logs-*.txt`。Native API 仍为 39，没有向第三方 BPK 开放其他应用的日志。

## 存储与写入

- `/bpkfs/system-logs/`，32 个至多 32 KiB 的分段，文件大小总上限 1 MiB（包含分段头，不包含文件系统元数据）。与应用共享内部 LittleFS；不改分区，不擦除用户数据。
- 原有串口输出保持。日志钩子只格式化到有界记录并非阻塞入队；原生低优先级线程写盘，两秒刷盘，队列满时丢弃并计数。只保留 WARN/ERROR，以及 OuseCore/Installer/Identity/Health 的 INFO 事件；触摸、刷新、普通 JS 输出等 INFO 不保存。已知密码/令牌字段整行排除，这不是任意内容的自动脱敏保证。
- 单条原始文本最多 383 字节；终端控制码清理后保存。容量满淘汰最早分段，日界线也轮换；每分钟检查过期，UTC 时间已知时删除七天前的分段。因此七天是上限，容量/空间压力可能更早淘汰。
- 时钟尚未同步的记录保存 boot ID 与启动毫秒数。时钟有效后，未知时间分段从首次观察到有效时间起计算保留窗口，不反推原始日期；没有可靠时钟时不能保证实际七个自然日，容量限制始终有效。
- 内部空闲空间低于 128 KiB 时先回收旧日志并丢弃本次记录；写入错误和丢弃数在应用显示。清理不删除应用、设置或其他目录。
- 正常重启/关机在可靠性协调器完成其他写入后再等待日志刷盘。突然断电仍可能丢失最后约两秒以及尚未消费的队列。完整 panic/coredump 与 ROM 直接输出未接入普通日志钩子，仍需串口接收；本功能不能替代完整崩溃转储。

## 并发与导出

LVGL 只请求分页并复制 RAM 快照，不做磁盘读写；页窗重叠 512 字节，避免分段边缘丢失整条记录。后台关闭时暂停 UI 轮询，关闭后释放定时器。导出在日志线程进行，注册系统存储任务并持有 SD 租约，先写 `.part`，同步完成后重命名。成功显示文件路径，失败显示 SD 卡提示。导出文件属于用户文件，不随七天轮换自动删除。

调试串口 `DBG_LOGSTATE` 返回状态，`DBG_LOG` 通过已有 DBG_READ/DBG_FREE 资源通道读取当前分页快照。调试关闭时沿用统一拒绝策略。

## 验证

`python tools/test-journal.py` 使用实际日志 C 实现和真实临时磁盘，模拟时钟/RTOS 边界，覆盖筛选、敏感字段排除、重复关闭重开、断开串口也可持久化的文件路径、七天过期、未知时间、超过 1 MiB 的轮换、分页、重启恢复序号及 SD 文本导出。该测试的 AddressSanitizer 运行通过；原有真实 LVGL/ASAN 界面回归也通过。主固件完整构建通过。

真机仅更新 P4 应用区，未修改分区、NVS 或应用数据。最终固件 6,974,816 字节，SHA256 `69bd554ff9ac1697a0022d95a341f59ece5d51204d726b57c08f4d4882ddccf8`，烧录校验通过，DBG_BUILD 与所部署 ELF 一致。启动阶段关闭串口接收，之后仍可读取启动日志；连续重启后同时读取到两个启动记录。SD 导出最终为 2,338 字节，可查询大小与 CRC；确认清理后记录为 0。8 个 BPK ID 保持一致，设置未重置；堆检查正常，日志丢弃数 0，串口释放且无异常重启。诊断证据在 `.tools/diagnostics/journal-20261019/`。

复测发现并修复了 LittleFS 上 `access()` 不兼容导致已存在目录不能就绪的问题，改用 `stat()`，补充同一目录重复启动与导出目标不覆盖的回归测试。七天及超量轮换由模拟时钟的真实文件测试覆盖，未声称在真机上运行满七天。

## 应用商店版本规则

云端只接受同一 ID 下严格增加的 `versionCode`；当前不支持相同序号覆盖或更小序号回退发布。版本名为展示字段。数据库保留 releases 历史和不可变下载对象，但网页/接口没有历史版本选择或回退按钮。设备允许相同序号重装，拒绝更小序号安装。恢复旧代码的受支持方法是使用更高序号重新发布；应用数据结构的兼容性仍需由应用处理。
