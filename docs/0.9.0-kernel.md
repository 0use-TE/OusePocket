# 0.9.0 本地系统机制完善

本轮只完善原生任务管理、受控 JS 后台、执行保护和诊断；不加入音乐、下载、闹钟、倒计时、蓝牙或摄像头业务。不升级依赖，不改变分区、字体、真实 Wi-Fi/显示及已有显示等待修复。基线是本地提交 `e489dc8`，保留了原有整个工作区。0.8.0 的烧录和真机证据仍归原版本，本轮不沿用为 0.9.0 验收。后经用户授权，完成一次下载模式应用烧录与简短启动/通信确认。

## 任务与实例

`ouse_tasks` 是原生有界登记服务，不是新的线程池。实际调度继续使用原有 FreeRTOS 工作任务。每个应用实例在分配时获得本次启动期间不复用的 `instanceId`，它与切页/输入代次分离。任务持有 app ID 和实例编号等纯数据，不持有 JSValue、UI 指针或运行时实例指针。

- 任务状态：`queued → running → succeeded/failed`；可取消的运行任务先进入 `cancelling`，原生资源停止后才进入 `cancelled`。排队任务也必须由工作任务领取或原生提交层明确撤回后确认取消。请求取消不代表停止，已有不可撤销的成功提交也不因迟到的取消请求改写为失败。
- 音频：新请求替代排队请求时，旧请求立即撤回；替代正在运行的请求时只请求停止。现有块边界检查负责协作退出，codec close 完成后确认终态。关闭/更新/卸载及脚本故障都请求停止该实例的短音频。底层同步 I/O 不能由 QuickJS interrupt 强制抢占。
- Wi-Fi：序列化接受操作，忙时返回拒绝，不再无记录覆盖请求。已开始的操作当前不支持由应用强行取消；关闭实例后继续系统连接操作，取消投递。扫描超时先请求 scan stop，断开/关闭 Wi-Fi 等待对应原生事件后完成。缺失停止事件时保留在途记录并拒绝新操作，不假装完成或复用会话。持续连接与重连状态仍读 Wi-Fi 快照，已成功连接任务的历史结果不会被后续断网改写。
- 私有存储：排队请求可显式取消；工作任务原子领取后不再允许取消，读写安全收尾。Home 不阻止已接受 I/O；挂起时保留 Promise 结果及终态投递，恢复后处理。关闭撤销 resolver 和投递资格，并释放存储请求持有的完整实例引用；未完成原生请求仅保留自身有界请求/结果缓冲，不再拖住整个旧页面/资源模型；卸载保留 FIFO 排空与数据清理屏障。更新保留私有数据。
- 包安装/卸载：以 system 原生任务登记，校验、写入、UI 激活/移除和卸载存储屏障完成后才记录终态。UI 只提交隔离校验，最长两秒的等待移到安装任务，界面不等待 JS 编译。安装前完整校验、临时文件替换和已有恢复规则保留。
- 设置保存：实际提交批次登记为 system 任务，已有请求合并机制保留，不为每次滑条变化创建硬件任务。登记容量异常不能阻止设置落盘，登记失败计入 rejected。

任务表最多 96 条，全局最多 64 个活动任务；每实例最多 8 个活动任务与未交付终态之和，原有存储在途上限仍生效。活动记录、未交付终态不回收；容量压力按最早任务 ID 回收已交付或已脱离实例的终态，无永久历史保证。实例关闭后释放投递钉住状态，但原生未停止的活动任务仍占容量。ID 耗尽时拒绝分配，不回绕。队列或内存不足会明确拒绝/记录失败，不增长无界队列。系统重启清空任务历史。

## JS 接口

```javascript
Ouse.tasks.onComplete(task => {
  // id/appId/instanceId/kind/operation/state/result/error/errorCode
  // cancelRequested/cancellable/cancelReason/closePolicy/detached
  // createdMs/startedMs/finishedMs/revision
  // result: 运行中为 null；终态为 {ok, ...原生结果摘要}。
});
const id = Ouse.wifi.scan(); // 接受：正整数任务 ID；拒绝：false
const task = id ? Ouse.tasks.get(id) : null;
const mine = Ouse.tasks.list(0, 16); // 当前实例；按 ID 升序，每页最多 16 条
const next = mine.length ? Ouse.tasks.list(mine[mine.length-1].id, 16) : [];
const systemTasks = Ouse.system.tasks(0, 16); // 只读系统任务诊断，包含脱离实例的收尾任务
const accepted = id && Ouse.tasks.cancel(id); // 不支持当前阶段取消时 false
const write = Ouse.storage.set('example', {value: 1});
const writeTask = write.taskId; // 本地校验拒绝时可能没有 taskId
write.then(value => { /* JSON 结果 */ }, error => { /* 处理错误 */ });
Ouse.tasks.onComplete(null);  // 解除订阅
```

音频 testTone/record/playRecording/stop、Wi-Fi setEnabled/scan/connect/disconnect/forget 返回任务 ID 或 false；音量、静音、设置等短同步接口仍返回布尔接受结果。查询失败或不属于当前实例返回 null，不允许跨实例取消。完成监听每实例一个，可替换/解除；没有监听时可运行实例仍消费投递槽以允许回收。挂起时不运行监听，不消费投递。每个终态最多交付一次，不在订阅时重放已消费事件。原生停止与 JS 投递是两个阶段，任务终态可以先于存储 Promise 的投递；存储 JSON 内容只在 Promise 中交付，登记表不复制私有值。终态 result 含 ok；Wi-Fi 摘要保存 enabled/connected/networks/reason/ssid/ip，音频保存 recordedMs/positionMs，成功存储保存 jsonBytes；这些均为完成时的有界副本，不随硬件后续状态变化。切页保留实例；页面专用结果仍需应用检查页面代次。

## 后台与原生服务接入

```javascript
// manifest: capabilities.background = true
Ouse.background.begin('sync-progress'); // 原因 1..63 个 UTF-8 字节
Ouse.background.get(); // lifecycle 快照，含 reason/sinceMs/instanceId/alive
Ouse.background.end(); // 撤销 JS 后台许可；回到默认挂起策略
Ouse.diagnostics.get();       // 当前实例缓存；首次快照前可能为 null
Ouse.system.diagnostics();    // 系统任务/JS/应用缓存与预算口径
```

每实例一个幂等后台申请，重复 begin 更新原因，不累积引用；无参数使用 application。申请可在前台建立，只有退到后台时才使用后台预算。end 在前台不暂停 JS，在后台冻结计时器和普通 Promise/任务事件；它不撤销已接受的存储或 Wi-Fi 工作，也不删除通知。实例关闭/故障会撤销后台申请，工作任务清理 JS 回调、定时器与 Promise；清理不依赖应用 onClose 成功。

四个状态独立：实例存活不等于 JS 可运行；JS 挂起不等于原生任务停止；持续通知只是一条消息记录。通知不会授权 JS、保持实例或启动原生工作。Home 默认保留实例；已接受的短原生音频/存储/Wi-Fi 可以自行完成，即使 JS 未申请后台；音频关闭策略仍为 stop。

未来原生服务通过 `ouse_task_create/start/finish` 登记真实工作，通过 finish-on-close/stop-on-close 声明原生生命周期。应用关闭时登记层撤销旧实例事件，并按策略请求取消；服务在安全边界检查取消、释放硬件后确认终态。需要独立于实例长存的原生服务使用系统服务所有权，并由服务维护自己的会话/授权和显式结束接口，不用常驻 JS 或通知替代服务生命周期。本轮不开放任意后台线程、定时唤醒或无限制 JS 执行。

## 执行保护与统计口径

固定 IDF 6.1 的普通双核 FreeRTOS 内核在任务切出时累计运行时间；`vTaskGetInfo()` 不包含当前尚未切出的片段。因此不能只读一次该值检查死循环。本轮开启 ESP timer 时钟、64 位任务运行累计值，每个预算起点及约 1 ms 的 interrupt/原生解析检查点实际阻塞一个 tick，促使内核结算，再读取共享 JS 工作任务的累计值差。

前台/后台分配时间上限仍为 **12/4 ms**，启动各阶段仍为 **100 ms**。单一 JS worker 内每实例的片段单独记账；任务被抢占、等待锁以及主动让出的 tick 不计入该运行累计值。当前片段的计数在下一个检查点才结算，存在检查间隔及 QuickJS interrupt 频率造成的超调；不能承诺硬实时截止。

该值称为 **FreeRTOS 任务获调度时间**（`freertos-task-scheduled-us`），包含该任务执行的原生绑定、引擎开销，以及内核归入该任务的中断时间，**不是纯 JS CPU 执行时间**。所有原生绑定仍须使用有界快照/短提交，耗时 I/O 仍由服务任务执行。不能用该保护抢占任意阻塞 C 驱动。

保护有两层：当前 JS 回调按任务获调度时间中断死循环；回调返回后若普通经过时间片已耗尽，就延后后续回调而不判脚本错误。前台优先、每实例每轮一个片段、事件/Promise 数量上限保留。另设 1 秒普通/2 秒启动的经过时间紧急熔断，独立记录 wall_guard，防止异常总耗时无限延长；这不是将正常 12/4 ms 执行限额统一提高。日志同时报告计时口径、分配时间、经过时间、上限和检查次数。

开销：启用 FreeRTOS 运行统计后，每次上下文切换增加时钟读取和累计操作，每任务增加运行统计字段；预算起点及约 1 ms 检查点让出一个 1 kHz tick，增加回调墙钟延迟。实际板上代价尚需真机确认。主机保护使用明确标注的 host-elapsed-us 后备时钟，专门原生测试用确定性调度时钟验证算法，不据此推断硬件时序。

诊断只复制缓存；JS heap 使用 `JS_ComputeMemoryUsage().malloc_size`，最多每实例每秒采样一次，并返回 memorySampleMs，不再每调度轮遍历所有 JS 堆。nativeKnownBytes 仅为实例结构、源码和复制资源的已知字节，不包含 LVGL、RTOS 队列/锁、分配器元数据和所有原生服务缓冲，不能称为应用总内存。系统可用堆仍由 system.info 提供，文件系统物理占用与逻辑文件长度仍按原有口径区分。任务登记表返回固定占用字节及容量，后台 JS 数不代表原生任务数，CPU 频率不代表 CPU 使用率。

## 验证边界

分类接口测试增加任务提交/取消、终态显示与后台原因，硬件请求按返回的任务 ID 查询，不再用全局最新编号推测该应用结果。资源监视增加任务、后台和预算口径。

本地统一验证与最终 IDF 构建已通过；随后按用户追加授权完成应用区烧录和简短启动/通信检查，不宣称完整真机功能验收。新硬件能力、协议、解码器和系统服务仍可能要求固件更新；现有 JSON＋JS 能力内的应用可独立打包安装。

编辑器预览同步提供 tasks、后台原因与诊断接口，数据标记 simulated，预算口径为 preview-simulated。它只模拟接口与交付流程，不测量 ESP32 内存/调度，也不替代 QuickJS 的执行隔离或设备测试。
