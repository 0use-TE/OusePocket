# 0.8.0 紧凑面板与应用子页面

本轮范围是原生快捷面板、BPK 子页面导航和分类接口测试应用。系统核心与设置保持原生，接口测试保持独立 BPK，并在真机验收后保留安装。依赖、Flash 分区和字库方案不调整。核心 C API 为 8，JS API 为 1。

当前源码已构建、烧录并完成五套真机验收：面板 6 组、导航 10 组、框架 14 组、资源/私有存储 12 组、最终分类 API 17 组均通过。接口测试首页直接显示应用名，Wi-Fi 分批刷新；早期超时和中间包错误证据保留。最终 API 与清理无新增错误，未见系统 panic 或意外重启。Calculator 与接口测试 BPK 保留，COM10 已释放；按用户要求停止追加测试。

## 快捷面板

头部约 64 dp，紧凑显示时间、日期和设置入口；双列两行提供 Wi-Fi、电源、声音、主题四个独立快捷项，每项约 64 dp 高，显示实际连接、供电、声音和主题状态。声音进入原生声音设置第 6 页，主题直接切换明暗；下方仅有一条约 56 dp 高的胶囊，包含垂直居中的 24 dp 太阳图标和宽亮度滑条。面板不显示亮度、音量或电量数值百分比，不再有音量滑条和小主题/静音按钮。按钮触摸区域至少 44 dp；语言、字号仍在设置。

保留顶部左右分流、跟手下拉、手势关闭、通知中心与明暗主题；布局根据 dp/sp 和文字行高适配，不改变全局 DPI。

320×480、160 DPI 的布局首屏显示全部四项和亮度，100%/115%/130% 字号均按实际行高分配标题和状态区域。长 SSID/状态单行省略，避免进入另一张卡片；不为了填满空白增加未实现的快捷功能。`tools/test-device-quick-panel.py` 使用真实指针、控件树和 LCD JPEG 检查六组主题/字号，先前固件结果与当前重验分别登记。

## 子页面

同一 page.json 中定义 initialPage 与 pages 数组，最多 16 页，导航栈最多 8 层；每页独立最多 96 个节点。每次只建立当前页控件，页面定义共用单位和词表；单 root 页面仍使用 main 页面 ID。

`Ouse.navigation.push/back/replace/get/onChange` 提供异步页面切换。界面任务释放旧页面后，脚本任务建立新模型，再由界面任务建立控件、完成布局并通知应用绑定事件。旧页面事件按代次丢弃，切页清理输入法、下拉选项、弹层和图片缓存。JS 上下文、计时器、私有存储请求继续存在；返回重建该页，业务值由应用恢复，当前不恢复滚动位置。

系统返回顺序为输入法、系统/应用模态、应用子页面、桌面。导航与应用生命周期分开；Home 保留当前导航栈，显式关闭后再打开回初始页。

页面变更通知先于延期 Promise 和存储结果绘制；应用在 `onChange` 中绑定当前页事件并恢复业务值。计时器与异步任务不会因切页自动取消，页面专用任务应自行停止或检查页面进入代次，避免旧结果写入新页。页面总文件大小和其他 BPK 配额不因页数增加而放宽，也不增加另一种 BPK 格式。

## 接口测试

`user.api-test` 首页左上角直接显示“接口测试 / API Test”，不提供“桌面”按钮；下方提供显示外观、音频麦克风、Wi-Fi、电源系统、控件输入、通知后台、资源存储七类。复杂项目继续进入细分页面，子页顶部返回与标题保持可见，只刷新当前页数据。

设备异步操作根据请求完成和实际状态展示结果；接受请求不等于硬件执行成功。新增测试资源随 BPK 打包，私有测试数据使用应用自己的空间。后台和通知显式声明能力，后台测试由用户主动开始。

最终 `dist/bpk/api-test.bpk` 为 **72,433 字节**，SHA-256 `c570f949d90e3a64520ca717cc5f3fdacd49023cbdf57070101bf7ebc52c409d`，包含首页调整与 Wi-Fi 分批刷新。输入 change 反馈移到固定结果栏，避免反馈改变输入页布局。接口测试应用与用户原有 Calculator 包及私有数据保留，未作为临时测试包清理。

## 本轮定位的执行问题

### Wi-Fi 页面周期重绘与调试查询压力

旧包在 Wi-Fi 页每 500 ms 全量处理七个 AP 的文字和显隐，在密集 `DBG_TREE` 查询压力下触发定时器超时；首次缓存修正仍在入页导航回调达到 14.2 ms 并超时。初始首页与英文标题边界正常（`10,58,309,85`），问题不归因于首页标题。失败证据保留为 `device-080-current-api/api-app-result.json`、`device-080-current-api-optimized/api-app-result.json`，不覆盖为成功；首轮清理未全部完成，最终独立清理已补齐。

优化前独立 A/B `.tools/diagnostics/device-080-wifi-timing-before/timing-result.json` 匹配当前 ELF：

| 查询条件 | 时长 / 查询次数 | 新增 JS 错误 |
| --- | --- | ---: |
| 不查询控件树 | 30.0 秒 / 0 次 | 0 |
| 密集控件树查询 | 1.23 秒 / 5 次 | 1 |

最终只调整 BPK：`put()` 先比较原始 String 缓存再做 UTF-8 截断和原生更新，AP 显隐按变化更新；Wi-Fi 入页/`onChange` 启动批次，绑定与绘制每 **100 ms 最多两行**，使用页面 epoch 和数据 generation 守卫，暂停/关闭取消批次。周期绘制仅保留音频、电源和消息页。中间 20 ms 定时器低于 API 下限，已修正为 100 ms。没有修改固件、脚本预算或 Wi-Fi 驱动；最终 API 十七组 110.6 秒通过且无新增错误，额外优化后压力计时按用户要求中止。

### 页面初始化与字符串迭代

首次 16 页包被拒绝，原因是所有页面校验共用原先单个初始化阶段的 100 ms 时限。已改成上下文/JSON/catalog、每页校验、初始模型和编译/首次求值分别有界；每页校验后让出一个 tick，安装验证调用者仍最多等待 2 秒。常规前台/后台 12/4 ms 没有提高。

分类应用初次语言切换曾触发 JS 超时，并显示重复首字符。真机最小对照使用 `320中文😃`：`for...of` 和手动 `iterator.next()` 都重复返回 `3`，显式 UTF-16 索引能返回正确字符。QuickJS-NG 0.14.0 的字符串迭代器把 `uint32_t` 索引转为 `int *` 传给推进函数；本机 GCC 15 RISC-V 的 `uint32_t` 为 `unsigned long`，开启严格别名优化时该写入可能被优化器忽略。项目仅为 QuickJS 组件加入 `-fno-strict-aliasing`，保留 `-O2`、固定版本和 managed 源文件。

真机 A/B 对照已完成：

| 方法 | 修正前 | 修正后 |
| --- | --- | --- |
| 有次数上限的 `for...of` | 连续八个 `3` | `3, 2, 0, 中, 文, 😃` |
| 手动迭代器连续八次 `next()` | 连续八个 `3` | 六个正确字符，再两次 `DONE` |
| 显式索引并按码点推进 | 六个正确字符 | 六个正确字符 |

修正前证据为 `.tools/diagnostics/device-080-string-before/string-result.json`，诊断 ELF `5d6d2ad11a2550189ee7d44f5d40e52a5d115883b933f40cd09cfedad0add6f3`；修正后为 `.tools/diagnostics/device-080-string-after/string-result.json`，诊断 ELF `258d0f0bbfca176917d234f2488aaacb6ad768d34ca1da52112f15647f0a4e2c`。两次均登记串口已关闭；这些是独立诊断构建身份，最终主题固件身份见验证表。

接口测试的文本截断另使用显式 codePoint 索引推进、按 UTF-8 字节限制，保留正文换行并可视化 NUL；私有 JSON 通过 JSON.stringify 展示，避免合法 JSON 字符串中的 NUL 直接交给 LVGL 文本。存储回调按页面进入代次控制绘制，旧页面结果不会覆盖新页面。
