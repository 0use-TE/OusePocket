# 0.7.0 应用框架第三阶段

第三阶段提供 BPK 包内资源、应用私有持久化和实际存储统计。核心版本为 0.7.0，公共 C API 为 8，JS API 为 1；只有一种 BPK 格式，依赖版本保持固定。

## 实现

| 范围 | 行为 |
| --- | --- |
| 包内资源 | 清单声明 image/text/binary；严格校验 ZIP、资源路径、类型和配额；图片可供页面直接显示或通过 setImage 切换 |
| 只读 API | assets.list 返回元数据，readText 读取 UTF-8，readBytes 返回独立 ArrayBuffer 副本 |
| 私有数据 | storage.get/set/remove/keys/clear/info 全部返回 Promise，数据按原生应用 ID 隔离 |
| I/O 线程 | 独立存储任务负责 LittleFS 读写、配额扫描和 fsync/rename；UI 和 JS 不执行文件 I/O |
| 生命周期 | 已接受请求可在关闭后完成；挂起只保存完成结果，恢复后投递；更新保留数据，卸载关闭实例后通过 FIFO 屏障删除数据 |
| 启动恢复 | 卸载中断留下的孤立数据在启动时清理，仅包文件明确不存在才认定为孤立；损坏但仍存在的包保留数据 |
| 资源监视 | 区分物理 Flash 容量与 LittleFS 使用量，显示总量、已用、可用、安装包字节及应用数据字节 |
| Promise 调度 | 每执行片段最多 8 个微任务，剩余延后；正常的长 then/await 链不会仅因超过 8 个任务而失败，单个同步任务仍受时间预算限制 |
| 启动预算 | 上下文初始化与初始页面解析、隔离编译验证、首次脚本求值分别使用 100 ms；常规前台回调仍为 12 ms、后台为 4 ms |
| 串口 | 应用日志、OPK1 安装、电脑控制/MCP 默认 921600；ESP-IDF 选用自定义 UART0，原 TX37/RX38 不变 |

资源和实例完整复制，更新时先清理旧 LVGL 图片/缓存再释放对应资源。异步存储请求持有实例引用，原生回调仅入队纯数据，不调用 JS 或 LVGL。JSON 序列化可能执行应用的 toJSON/getter，因此槽位及配额的最终检查位于序列化之后，避免嵌套提交覆盖请求。

100 ms 是各初始化或编译阶段的预算，不是整个应用打开或包验证流程的耗时保证；编译验证调用者最多等待 2 秒。普通事件、生命周期回调和后续 Promise 调度继续使用常规执行片段，任意原生 C 操作仍不能被这些预算强制抢占。

存储统计是线程安全缓存：文件系统 total/used/free 包含 LittleFS 元数据；packageBytes 是已提交 BPK 文件长度之和，privateBytes 是已提交 JSON 内容长度之和。逻辑字节不应与物理已用字节混为一谈；CPU 仍显示配置频率，本阶段没有提供 CPU 占用率。

## 应用契约

包上限 512 KiB，清单 8 KiB，页面与脚本各 32 KiB。四个必备文件加清单中精确声明的资源文件，最多 16 项资源。图标仍是最大 96×96 的 OIC1；页面图片最大边长 512、像素累计 128 KiB。text/binary 累计另有 128 KiB；每个 text 最大 16 KiB、有效 UTF-8 且无 NUL，binary 最大 64 KiB，可为空。源 PNG 可在电脑打包时转换，预转换二进制资源不依赖 Pillow。

每应用最多 32 个私有键、64 KiB 已提交 JSON 内容，每个值序列化后最多 8 KiB。key 为字母/数字开头的 1～31 字节 ASCII 名称，后续可用点、下划线、连字符。接口不接受任意文件路径或其他应用 ID。set 采用标准 JSON.stringify 语义，成功代表原子替换已完成；缺失 key 的 get 返回 null。

每实例最多 8 个未完成存储请求，全局最多 64 个（包括已关闭但原生回调未到的请求）。原生队列容量 16，忙时拒绝提交；应用应等待/处理 Promise。未声明主动后台运行的应用仍默认冻结 JS，接受过的文件操作由原生任务完成，不代表允许后台业务脚本继续执行。

完整用法见 [BPK 契约](bpk.md)，实现边界见 [运行时说明](../components/ouse_runtime/PORTING.md)。本阶段不包含中文拼音候选、音乐解码、原生闹钟/倒计时或云端账号。

## 修正与验收边界

首轮 `device-070-phase3/` 保留为 failed：旧构建把初始化也限制为普通回调的 12 ms，约 40 ms 的应用初始化被误判为超时。已为各启动阶段单独设置有界 100 ms 预算，日常 12/4 ms 保持，最终构建在上述测试中通过。

`device-070-phase3-2/` 是同一最终固件的测试等待错误：921600 下，脚本在异步页面创建前读取并立即要求文本存在；已改成等待真实 ready 文字。`device-070-final/` 则是报告助手查询显示状态时漏传 status，被协议拒绝；修正后结果保存在 `device-070-final-2/`。失败记录均保留，未用后续成功覆盖。

本轮验证 1 次硬件复位后数据保留，未做完整断电冷启动、写入中断电、长期磨损或长时间并发验收。PNG 转换路径需要 Pillow；本机 IDF Python 未装 Pillow，实际资源测试使用预转换 OIC1，未把 PNG 转换计为通过。图片当前为未压缩 BGRA8888，不含 PNG/JPEG 解码或音乐流式资源接口。通知回归沿用第二阶段能力，本轮未再次执行完整通知中心专项测试。

应用日志、安装与 MCP 的运行速率为 921600。此次只烧录应用，ROM/旧 bootloader 的最初输出可能仍为 115200，进入应用后使用 921600；这不表示运行时安装服务速率不一致。
